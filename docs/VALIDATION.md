# 0.1.0 验证记录

本机验证环境为 Windows x64、Rust MSVC stable、Node.js 24。以下只记录实际验证内容，不代表所有 Windows 版本或硬件均已覆盖。

## 自动化检查

`cargo test -p foldsentinel --locked` 的 13 项测试全部通过，覆盖：

- 空文件、二进制文件、Unicode 文件名、嵌套目录及空目录的往返恢复；
- 错误密码、类型 / salt / nonce / 密文 / 标签篡改及截断不生成输出；
- 大文件限额、已有输出、最终提交竞争不覆盖现有数据；
- 路径穿越、Windows 保留名称、特殊文件和归档链接拒绝；
- 属性重复应用后仍可还原原始位；
- 状态文件锁、损坏状态报错，以及状态保存失败时不修改文件属性。

`cargo clippy --workspace --all-targets --locked -- -D warnings`、Rustfmt 和 `npm run build`（TypeScript 严格检查 + Vite）通过。CI 在干净的 Windows runner 上另外执行整个工作区测试和构建。

## 原生桌面操作

通过真实 Windows 窗口完成以下流程，未替换后端或模拟成功：

1. 将包含中文文件名及空目录的隔离测试文件夹创建为 `.fse` 加密包；磁盘上出现加密包，界面显示真实字节数，密码框清空。
2. 将该加密包恢复到新文件夹；原文件与恢复文件 SHA-256 相同，空目录存在，源数据仍然保留。
3. 在属性页面为恢复目录应用隐藏与只读，检查文件系统实际属性；通过同一页面恢复，属性回到 Archive，恢复记录变为空。

已构建 NSIS 安装包。便携程序在本机具备 WebView2 的环境中启动；未在缺少 WebView2 的干净虚拟机上安装，也未测试不同用户 ACL、网络断开、断电或强制终止的恢复行为。这些限制不应被解释为通过了独立安全审计。
