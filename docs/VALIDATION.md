# 验证记录

## 0.3.0 — 2026-10-24（本机验证）

Windows x64 本机 30 项 Rust 工作区测试、5 项前端工作流测试、Rustfmt、Clippy `-D warnings` 与 TypeScript/Vite 构建通过。新增验证覆盖只读 v1/v2 文件及目录包、无输出与无验证任务登记、错误密码、各类篡改、缺失终块、归档文件/父路径冲突、验证取消、空间预检边界与错误分类。扩展路径测试在超过 300 字符的 Windows 路径下完成加密、只读验证、恢复；真实只读文件返回访问权限错误，已有目标保留，源文件独占句柄占用导致失败且无输出。取消检查覆盖派生、加密、目录复核与同步阶段，提交门后拒绝取消。

前端测试确认分次选择路径追加与 Windows 路径去重、串行执行、失败后继续、暂停与等待取消、存储失败时不启动文件操作、历史白名单不含密码或密钥、重启把未完成状态标为中断，以及双语目录占位符一致。

真实桌面已验证：首次跟随中文系统语言、切换 English；两个文件与一个中文目录批量排队、串行加密成功；三个生成包只读验证成功且没有恢复输出；错误密码三项均报告认证失败；从失败历史重填时密码清空，输入正确密码后重试成功。英文原生选择框一次选入三个加密包并串行恢复，三个文件 SHA-256 与源内容一致，中文名称与空目录保留。切回中文时历史、状态和认证错误即时翻译；分别重启后保留 English、简体中文偏好及历史。

4 GiB 零数据独立夹具仅用于交互时长，不计入性能数据：显示真实字节、速度和预计时间，取消后无最终输出，后续小任务正常完成。运行时点击关闭先取消当前任务并暂停队列，清理后再次关闭；重启时等待项显示中断，密码为空，没有自动执行或临时数据残留。窗口缩窄到约 720 px 后英文控件、队列与重试按钮完整显示；中文文件夹选择标题正确。原生系统按钮遵循 Windows 语言。

独立子进程在加密的 deriving/encrypting/syncing/committing 和恢复的 deriving/decrypting/syncing/committing 共 8 个阶段被真实终止。每项均无最终输出，识别并清理自有残留，源内容保留，重新执行后内容一致。报告见 [v0.3 中断报告](validation/v03-crash-windows-x64.json)，重现命令如下（报告位置须尚不存在，夹具自动清理）：

```powershell
cargo run --release --example validate_v03 -- --report .\v03-crash-result.json
```

最终构建中，英文空表单报告 `Please fill in this field.`，没有创建任务；切换中文时页眉标语与同一错误即时翻译。Windows CI 与附件校验和以同版本 [Release](https://github.com/JC-zyb/foldsentinel/releases/tag/v0.3.0) 所链接的提交和 `SHA256SUMS.txt` 为准；本机通过不等于远程 CI 已通过。

用户手工确认：从资源管理器单独拖入文件、文件夹均能填入路径，多选后一次拖入可同时填入。原行为是后次拖入替换列表；现已改为选择及拖放共用追加去重逻辑，追加边界由前端测试覆盖。新构建的原生选择框依次选入 alpha.txt、资料文件夹，列表同时保留两项；再次选择 alpha.txt 后仍只有两项。用户进一步复核修正后的连续拖入：先拖入 alpha.txt，再单独拖入资料文件夹，最后重复拖入 alpha.txt，两项均保留且无重复。跨窗口拖放由用户手工完成，工具未代做。

限制：空间不足仍以边界检查和有状态失败写入器验证，未实际写满整盘；未进行断电、硬件故障、干净虚拟机安装或独立安全审计。Windows 原生文件对话框的系统按钮遵循操作系统语言，应用负责其自定义标题。

## 0.2.0 — 2026-10-24

本机为 Windows x64、Rust 1.99 MSVC、Node.js 24。工作区 24 项测试、Rustfmt、Clippy（`-D warnings`）和 TypeScript/Vite 构建通过。除原有属性/状态测试，覆盖：1 MiB 块边界、空文件、Unicode 与 GNU 长名称、v0.1 发布源码生成的两个兼容夹具、头部/标签/密文篡改、错序、截断、追加、tar EOF 仍须验证认证终块、扩展元数据限额、取消加密和恢复、分块中途模拟磁盘满、源目录变化、提交竞争，以及活动锁与最终输出保护。

以下使用 release 核心验证程序，**真实写入完整字节并进行加密/恢复**。每个文件重复一个随机生成的 1 MiB 块，无压缩；不是稀疏文件或仅设置文件长度。源文件和恢复文件均逐一核对 SHA-256。10 GiB 目录由 10 个 1 GiB 文件及中文空目录组成。

| 内容 | 加密 | 恢复 | 核心进程累计峰值工作集 | 结果 |
|---|---:|---:|---:|---|
| 4 GiB 文件 | 9.49 s | 13.99 s | 24.59 MiB | SHA-256 一致，源文件保留 |
| 10 GiB 文件夹 | 34.92 s | 38.10 s | 24.65 MiB | 10 项 SHA-256 一致，中文空目录保留 |

内存使用 Windows `GetProcessMemoryInfo / PeakWorkingSetSize`，阈值为 256 MiB；该数字属于核心验证进程，不包含 WebView2。桌面长任务实测 FoldSentinel 主进程峰值约 52.9 MiB，也不含独立 WebView2 子进程。时间受磁盘、系统缓存及并发负载影响，仅代表本机结果，不是性能保证；1 TiB 是实现限制，未做 1 TiB 实测。

表格记录在收紧 tar 元数据解析后重新执行的结果；此前同规模验证也通过，峰值 25.92 MiB。完整哈希和测量值见 [大数据报告](validation/v02-large-windows-x64.json)，真实终止结果见 [中断报告](validation/v02-crash-windows-x64.json)。

真实强制终止验证：子进程处理 32 MiB 隔离文件，在 payload 写入完成、提交前被父进程终止；最终输出不存在，重新启动后识别中断记录、清理专属 staging、核对源文件，再次加密恢复的 SHA-256 通过。不是用错误返回或 Mock 替代进程终止。

原生窗口验证：显示中断任务 → 清理临时数据并重填路径 → 重新输入测试密码后生成真实加密包；长任务显示已处理字节和百分比，点击取消后返回“未提交输出”，密码清空，磁盘无最终输出、无 staging、无任务记录。长任务取消测试使用单独的 16 GiB 零数据夹具，仅用于交互时长，未作为上述大数据往返或性能数据。

可复现命令（先指定有至少 33 GiB 空间的现有临时盘，JSON 报告路径必须尚不存在）：

```powershell
cargo build --release --example validate_v02 --locked
.\target\release\examples\validate_v02.exe large E:\ .\large-result.json
.\target\release\examples\validate_v02.exe crash E:\ .\crash-result.json
```

程序仅清理自己创建的随机临时目录，报告保留哈希和测量值。大数据验证不进入每次 CI，普通边界及错误路径测试进入 Windows CI。本地 NSIS 安装器与便携包构建通过；发布附件及校验和见 [Releases](https://github.com/JC-zyb/foldsentinel/releases)，干净 Windows runner 的构建状态见 [Windows build](https://github.com/JC-zyb/foldsentinel/actions/workflows/windows.yml)。

未覆盖：断电、硬件故障、完全写满真实磁盘、缺少 WebView2 的干净虚拟机、不同 ACL/网络文件系统、独立安全审计。磁盘满通过有状态失败写入器覆盖错误传播，不能代表所有设备行为。中断恢复为清理重试，不是断点续传。

## 0.1.0 历史记录

本机验证环境为 Windows x64、Rust MSVC stable、Node.js 24。以下只记录实际验证内容，不代表所有 Windows 版本或硬件均已覆盖。

### 自动化检查

`cargo test -p foldsentinel --locked` 的 13 项测试全部通过，覆盖：

- 空文件、二进制文件、Unicode 文件名、嵌套目录及空目录的往返恢复；
- 错误密码、类型 / salt / nonce / 密文 / 标签篡改及截断不生成输出；
- 大文件限额、已有输出、最终提交竞争不覆盖现有数据；
- 路径穿越、Windows 保留名称、特殊文件和归档链接拒绝；
- 属性重复应用后仍可还原原始位；
- 状态文件锁、损坏状态报错，以及状态保存失败时不修改文件属性。

`cargo clippy --workspace --all-targets --locked -- -D warnings`、Rustfmt 和 `npm run build`（TypeScript 严格检查 + Vite）通过。CI 在干净的 Windows runner 上另外执行整个工作区测试和构建。

### 原生桌面操作

通过真实 Windows 窗口完成以下流程，未替换后端或模拟成功：

1. 将包含中文文件名及空目录的隔离测试文件夹创建为 `.fse` 加密包；磁盘上出现加密包，界面显示真实字节数，密码框清空。
2. 将该加密包恢复到新文件夹；原文件与恢复文件 SHA-256 相同，空目录存在，源数据仍然保留。
3. 在属性页面为恢复目录应用隐藏与只读，检查文件系统实际属性；通过同一页面恢复，属性回到 Archive，恢复记录变为空。

已构建 NSIS 安装包。便携程序在本机具备 WebView2 的环境中启动；未在缺少 WebView2 的干净虚拟机上安装，也未测试不同用户 ACL、网络断开、断电或强制终止的恢复行为。这些限制不应被解释为通过了独立安全审计。
