# 文件保护方式

当前源码提供六种可选保护方式。已发布的 v0.6.0 二进制不包含本次锁定功能。

| 能力 | 当前行为 | 边界 |
| --- | --- | --- |
| 不保护 | 恢复登记前的属性与 DACL，并移除对应记录 | 原本就隐藏或只读的项目仍保持原始属性 |
| 隐藏 | 新策略设置 Hidden + System | 显示受保护系统文件或使用其他工具后仍可见；路径和内容仍存在 |
| 锁定 | 递归为已有项目添加针对当前用户 SID 的拒绝 ACE | 阻止内容读取、写入、目录枚举与新建子项；保留恢复权限 |
| 只读属性 | 为文件设置 Readonly 属性 | 文件夹不受该属性写保护；属性可由有权限的程序更改 |
| 权限只读 | 递归限制当前账户写入、追加、新建及目录内删除，保留读取和枚举 | 使用 NTFS DACL；已有句柄、其他账户及范围外父目录的删除子项权利仍有边界 |
| 隐藏并锁定 | 同时应用隐藏属性与 NTFS 锁定 | 兼有上述限制，默认选择 |
| 加密包 | 使用密码创建独立认证加密副本 | 源文件仍保留；先验证并试恢复，再决定原件如何保管 |

锁定仅支持具有权限修改能力的 Windows NTFS 文件和目录。系统目录、程序目录、用户配置根、包含恢复记录或当前程序的目录、重解析点及多硬链接在修改前拒绝。每个已有子对象单独保存原 DACL、继承控制、卷序列号、文件 ID 和创建时间；恢复日志先原子持久化，再修改权限。锁定从叶子到根设置受保护 DACL；恢复从根到叶恢复原 DACL 与继承，防止父项传播干扰子项。已锁定目录内的子项须从最外层登记项目整体恢复。

本地保护入口不会更改所有者、SACL或系统账户。DACL允许同一账户修改权限以解除锁定，因此它不是应用密码或防管理员机制；其他账户、备份/恢复特权、离线访问、已经打开的文件句柄不在此限制内。拒绝DELETE和受保护目录的FILE_DELETE_CHILD可以减少删除和重命名，但父目录的删除子项授权仍可能允许删除/移动根项目，不能宣称绝对防删除。不会在保护范围外修改父目录。本地入口不自动监控新子项。

“权限只读”的模式值为 `readonly-acl`，原“只读属性”仍为 `readonly`。权限只读和锁定共享原始 DACL、身份及父权限恢复记录；切换时从最初原 DACL 重建新策略，并在变更前保存前一种策略，支持中断重试，不将拒绝规则叠加。该模式保留本程序恢复所需的元数据及权限修改能力，不承诺防止同账户主动修改权限。

恢复检查文件身份、原始/计划中的DACL，以及范围外父目录的继承权限。外部改动、路径替换、离线磁盘或缺失锁定路径会停止并保留记录。发生中断时，记录中的原始状态和计划状态均可识别，可重复恢复；不要删除state.json或用旧程序覆盖它。

### 权限冲突后恢复

普通读取或枚举被拒绝本身不改变 ACL。资源管理器拒绝访问提示中的“继续”可能为当前账户新增永久授权；即使文件仍无法打开，登记的锁定权限也已经发生变化，普通解除会因此停止。

使用原有“解除保护”入口即可。该操作遇到权限冲突后会自动只读核查最外层项目的全部登记对象，检查身份、NTFS、链接约束、原始恢复资料及范围外父继承。只有完整带锁定资料的子树可进入确认；核查不会清理记录或写入权限，也不再要求用户找到另一个操作入口。

确认区域说明会撤销保护后新增或修改的权限，默认焦点在“取消”。点击“确认恢复原权限”后重新核查全部对象及状态摘要，再按父到子恢复原 DACL 和托管属性；文件内容不变，全部完成后才移除登记。刷新或核查后的权限/记录变化使确认失效；此时重新点击同一个“解除保护”即可再次核查。身份替换、缺失、范围外父继承变化或服务范围冲突仍不能跳过。核验、模式切换及 SYSTEM 服务的冲突策略保持不变。

## 服务密码访问

独立服务入口支持锁定、隐藏并锁定及权限只读，密码由Argon2id加随机盐派生并以认证资料验证；密码错误不修改保护状态。临时解锁默认5分钟，可选时长，截止/立即重锁由独立宿主执行；计划先保存再变更，宿主重启先处理未完成访问，失败保留记录并逐项显示。持续扫描为新子项先保存身份与原权限再应用策略，启用时修复已登记对象的权限漂移；身份替换或范围外父继承变化拒绝覆盖。

服务须另行安装，使用SYSTEM身份访问文件，并根据认证后的客户端SID生成限制，关闭GUI不停止服务。本机经用户确认完成真实安装、普通账户管道访问、到期与SCM停止/启动及异常恢复测试；第二账户与整机重启仍待验证。旧本地记录不自动迁移；服务恢复资料也不通过本地备份按钮导入。接口、安装和恢复边界见[持续防护服务](SERVICE.md)。

## 页面操作与核验

顶部“添加文件 / 添加文件夹”及当前页拖放只形成待保护清单。确认保护方式后，点击“应用保护”才修改属性或权限。列表只显示最外层名称和用户自定备注；可通过备注区分同名项目，搜索在全部根项目中执行后再分页。

“登记方式”来自恢复文件，选择不同方式会显示“未应用”。点击“应用更改”执行切换；保持原方式时“重新应用”再次处理所选范围，已锁定项目仅使用登记内容，不构成对新内容的持续监控。“解除保护”恢复记录中的原始属性与权限，原项目本来具有的隐藏或只读属性会保留。

“核验”是显式只读操作，仅检查登记项的托管属性；对于锁定项，还检查文件身份、计划锁定 ACL 及相关父目录权限。结果为“与记录一致 / 存在变更 / 无法核验”，并显示最近核验时间。它不枚举新增子项，不证明所有账户或已有句柄的实际访问都会被阻止，也不写回恢复文件。重启后须重新核验。

刷新失败保留最后一次成功记录，并暂停项目动作；点击“刷新”重试。操作和刷新分别报告，避免列表读取错误覆盖实际操作结果。用户备注最多 80 个 Unicode 字符，不接受控制字符，作为可选元数据随恢复文件保存；旧版 v3 工具可能在保存时丢弃备注，恢复字段仍兼容。

添加时每项可填写初始备注，完整恢复计划与备注一起持久化成功后才执行修改。批量操作分别显示成功、失败及逐项原因，“重试失败项”保留失败项原选择方式；批量解除先确认最外层名称、备注及数量。

顶部备份入口将完整恢复记录和文件身份封装为认证加密备份，随机密钥由当前 Windows 账户的 DPAPI 保护；只可在具备原 DPAPI 密钥的本机账户恢复，不作为跨电脑迁移。导出不覆盖文件。导入要求当前登记为空，并核对记录结构、身份、属性、ACL 和父继承；仅登记恢复信息，不修改文件，不覆盖已有记录。备份包含恢复敏感信息，应由用户保管。

GUI 使用项目名称和内部标识定位，不向页面传递父路径、子文件名或权限内容。CLI 可在 GUI 无法启动时恢复：

```powershell
foldsentinel-cli.exe protect C:\Private\Notes --mode hidden-locked
foldsentinel-cli.exe protect C:\Private\Notes --mode locked
foldsentinel-cli.exe status C:\Private\Notes
foldsentinel-cli.exe unprotect C:\Private\Notes
```

本机 NTFS 自动测试覆盖内容访问、目录枚举、新建拒绝、策略切换、原始权限恢复、重启、记录写入失败、中断计划、外部权限 / 身份冲突、父继承变化、缺失路径、硬链接及合并父目录。尚无干净 Windows 虚拟机、第二账户或原生 DPI 的本次验证，不将其列为通过。

技术依据见 Microsoft 的[文件属性常量](https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants)、[文件安全与访问权限](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)、[DACL 与 ACE](https://learn.microsoft.com/en-us/windows/win32/secauthz/dacls-and-aces)。这些资料描述 Windows 机制，不能据此推断特定闭源软件的内部实现。
