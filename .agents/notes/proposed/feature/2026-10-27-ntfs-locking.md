# Agent Note: 独立的 NTFS 锁定模式

Status: proposed

## Problem

Hidden/System 只影响文件显示，Readonly 对文件夹不提供写保护。用户希望在日常操作中阻止修改、删除或访问，但当前属性页不能提供这种访问控制。将权限改动混入隐藏会扩大恢复风险，也不能得到可靠的密码机密性。

## Proposal

将锁定作为独立能力，先在一次性 NTFS 测试环境验证。首个实验仅考虑针对明确 Windows 用户 SID 的防修改策略；读取限制作为另一策略评估，界面不得称为不可见或内容加密。应用密码只限制应用内操作，不能限制其他进程使用同一访问令牌，不承诺“只有本程序可解除”。现有加密包继续承担内容机密性。

锁定前读取并保存自相对安全描述符、原始 DACL 与继承控制位及卷 / 文件身份；恢复日志使用独立版本，不复用属性记录。先持久化，再改权限，逐项保留进度；恢复验证身份和当前 DACL，检测到外部变化时提示处理，不直接覆盖。初版不改所有者、SACL、系统目录、用户配置根或恢复资料目录，不部署驱动或服务。

设计依据：Windows 根据线程令牌和对象安全描述符授予访问；父目录 ACL 不直接决定每个已有子对象的权限，继承、既有句柄和父目录删除权限需要分别测试。[File security and access rights](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)。空 DACL 与无 DACL 含义相反，ACE 顺序和组成员权限会影响结果，不能使用 Everyone Deny 一概处理。[DACLs and ACEs](https://learn.microsoft.com/en-us/windows/win32/secauthz/dacls-and-aces)。备份 / 恢复特权和管理员恢复能力必须作为边界列出，不能以本机单一令牌实验替代多账户验收。

历史审计：[属性状态](../../implemented/feature/2026-10-27-attribute-status.md) 与[属性恢复](../../implemented/bug-fix/2026-10-24-recoverable-attributes.md) 部分重叠，仅复用显式状态与先登记原则，不能直接复用掩码恢复；[加密边界](../../implemented/architecture/2026-10-24-vault-and-desktop.md) 部分重叠，保留内容加密，锁定不替代它。没有完全吸收或废弃旧笔记。

## Alternatives considered

- 只用现有只读属性实现最简单，但目录不受其写保护，无法满足防删除 / 防写入；保留属性功能并单独评估 ACL。
- 对 Everyone 拒绝所有访问容易制造锁定效果，但也可能阻止本程序恢复，而且并不隔离相同令牌的不同应用；不采用此默认策略。
- 内核过滤驱动能拦截目录枚举和文件 IO，但增加签名、安装、系统兼容和故障恢复成本；本阶段不实现。

## Acceptance criteria

- 在隔离 NTFS 卷上，分别用标准用户和提升权限账户验证读取、写入、删除、重命名、复制、移动、父目录删除和既有句柄。
- 明确文件与目录、继承与显式 ACE、组成员、中文路径、重解析点和新子项的行为；不支持的位置在写入前拒绝。
- 中断、记录保存失败、外部权限变化、文件替换、卷离线后能保留可诊断记录；恢复原 DACL 和继承语义，源内容不变。
- 用户不依赖 GUI 也有经过实际验证的恢复路径；保护范围和恢复信息在最终确认前可审阅。

## Risks

当前没有干净 Windows 虚拟机和第二个测试账户，尚未进行 ACL 实验；本篇不代表已实现锁定。常规 DACL 无法保护管理员离线访问，也不能作为应用密码隔离。同一目录存在不同子对象 ACL、正在使用的句柄及外部策略时，恢复复杂度会增加。达不到恢复验收条件则不提供生产入口。
