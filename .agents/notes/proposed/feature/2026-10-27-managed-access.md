# Agent Note: 权限只读、密码临时访问与后台防护

Status: proposed

## Problem

只读属性不能限制目录新增或文件内容写入，现有 NTFS 锁定只能由同一账户直接解除，且新子项和外部权限改动不被后台处理。用户要求依次完成权限只读、原目录密码访问和持续防护；增加控件而没有完整恢复状态与运行机制会形成错误的保护承诺。

## Proposal

沿用逐项原 DACL、文件身份、先保存计划再修改的恢复机制。权限只读仅拒绝实际内容写入、追加、扩展属性写入和删除位，允许读取及枚举，不拒绝 GENERIC_WRITE 中与读取共用的 SYNCHRONIZE。切换模式必须从原始 DACL 重建所选策略，不能累加拒绝 ACE。

密码访问采用明确设置密码后启用的独立模式，使用既有 Argon2id 保存加盐验证资料，密码不进入日志、命令行或历史；GUI 和 CLI 都须通过核心入口验证。临时解锁保存截止时间和重新锁定计划，重新锁定可立即触发；后台进程负责截止处理，启动后先处理到期与中断状态。密码验证是本应用操作入口的边界，不宣称能隔离同一 Windows 账户直接修改 DACL、管理员或离线访问；现有加密包继续承担内容机密性。

用户已选择临时解锁默认5分钟，持续防护采用系统服务；完成代码后再确认安装。服务须使用独立身份，以目标用户 SID 生成策略，不能把 SYSTEM 当作受限制的用户。命名管道必须以 Windows 客户端令牌鉴权，并按 SID 隔离服务拥有的恢复状态；客户端指定的输入输出路径必须在客户端身份下验证权限，避免 SYSTEM 代理任意文件写入。关闭主窗口不等于停止。计划包括登记新增项、核对既有身份、按用户启用的策略处理外部权限变化，以及单项失败后保留恢复记录和明确错误。仅用户态的通知或扫描存在检测间隔与已有句柄窗口，不宣传为内核访问拦截。服务安装、系统启动配置及真实服务验证在具体实现可审阅后再取得授权。

历史审计：[独立NTFS锁定](../../implemented/feature/2026-10-27-ntfs-locking.md)部分重叠，本篇扩展策略和运行状态，保留其同账户及管理员边界；[文件保护工作区](../../implemented/feature/2026-10-27-protection-workflow.md)部分重叠，本篇增加独立的后台运行状态，不能把登记数量、核验结果或进程存在当作所有项目保护成功；[加密边界](../../implemented/architecture/2026-10-24-vault-and-desktop.md)部分重叠，保留内容认证加密及源文件保留，不改变加密包格式。未发现相应 rejected 或完全吸收的笔记。

## 服务宿主契约

`service`模块实现独立SCM入口和显式非SYSTEM前台调试入口。正式管道只接受本机客户端，使用overlapped IO、有限帧长和读写超时，等待客户端确认收到响应后断开。后台tick独立于等待管道输入，避免不发送请求的客户端阻塞到期重锁；所有核心变更仍串行持有状态锁。宿主先处理启动恢复，停止时先重锁；只有SCM运行并不等于每个根保护健康，Wire分别提供后台健康与逐根错误。

新登记在管道客户端模拟令牌下实际打开全树和祖先，不共享删除并持有句柄至SYSTEM核心登记结束；核心再次核对身份和最终路径。正式客户端在发送密码前将内核返回的管道服务器PID与SCM中固定服务的运行PID核对，并要求独立进程和LocalSystem配置；不接受服务器自报身份。首次真实SYSTEM安装暴露普通账户无法读取SYSTEM进程令牌（os5），因此移除生产入口的TokenUser读取，调试入口仍核对同账户令牌。SCM只需默认赋予本机用户的配置/状态只读权限，不给普通客户端调试特权。依据[OpenProcessToken跨账户限制](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-openprocesstoken)、[SCM进程标识](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-queryservicestatusex)和[服务配置查询](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-queryserviceconfigw)。管道使用FIRST_PIPE_INSTANCE，普通已认证用户只获得明确的读写位，不授予GENERIC_WRITE隐含的创建管道实例位；不信任请求内SID、状态路径或原始SDDL。

SYSTEM私有数据目录由已知ProgramData位置推导，按令牌SID分隔，严格核对受保护DACL和所有者，不接管曾由普通用户可写的目录。服务RPC不接受任意文件输出或恢复ACL导入；旧用户可改state.json需要先解除后再登记，避免把SYSTEM当作提权恢复工具。卸载拒绝尚有任何账户受管根或无法核对的状态；脚本不删除恢复资料或覆盖活跃服务。前台调试能验证管道和文件IO，不能代替SYSTEM、跨账户或SCM安装验收。

## 核心恢复状态机

`managed::ManagedStore` 与旧账户可写StateStore分开，由宿主在SYSTEM私有目录按经过客户端令牌鉴权的SID打开。新登记使用宿主持有句柄的授权身份清单，核心再次核对最终句柄路径与身份，自行读取原始ACL并为显式目标SID生成计划。属性与ACL均用核验后的句柄操作，不在核验后重新按字符串路径写入。

密码验证资料使用Argon2id（64 MiB、3轮、1路）及随机盐派生密钥，AES-GCM认证固定验证上下文；不保存密码。临时访问默认300秒，范围30–3600秒。先原子保存截止时间与opening中间位，再恢复原ACL及属性；成功后清除opening。错误密码不写状态或文件。opening中断、截止或系统时钟回退触发重锁，启动先处理未完成临时访问；停止前先重锁而不解除保护。日志不可写时仍按已保存的计划关闭已登记内容，保持未完成状态和错误供重试。

持续补查在后台身份下枚举，先保存新子项原始身份和ACL，再逐项应用策略。服务策略保留原ACE的子项继承规则，新拒绝ACE不继承，以免父项重锁剥空尚未补查子项的继承权限。身份替换、重解析点、硬链接、范围外父权限变化会停止该根并保留记录，其他根继续处理。启用监控时允许按用户已选择的策略修复相同身份对象的ACL漂移；关闭监控、解除和密码修改经过原密码验证。失败只返回根ID与稳定类别，不向GUI披露子项或ACL。

## 本地与服务范围互斥

StateStore的新增、模式切换、备注、解除与恢复备份导入都在文件或记录写入前查询服务受管范围。只读`CheckLocal`仅接受绝对规范磁盘路径，在宿主已加载的所有SID根上比较同根及祖先/子项，不打开请求位置、不返回根路径或SID，也不接收用户ACL。只有SCM明确返回服务未安装才允许本地写入；已安装却失联、无法查询SCM或响应损坏都明确失败。这样避免服务存在但停止时被当成空范围继续登记。

官方服务Enroll桥持续持有同一StateStore文件锁直到RPC完成；本地写入持锁跨过范围检查与实际提交，因此正常GUI/CLI两方向登记串行。该约束不把恶意同账户自制RPC、篡改state.json或管理员声明为新的安全边界。直接让SYSTEM读用户可编辑state.json虽然能在服务端统一检查，但会把不可信ACL基线引入特权恢复域；仅前端检查虽然实现短，却覆盖不了CLI和恢复导入，也无法保持检查与提交的时序。

互斥修复的核心3项和服务9项定向测试通过。实际console管道登记服务根后，同根、父目录和已存在子项的StateStore保护全部在写入前拒绝，local state不创建且属性不变；跨SID已登记服务根也参与只读比较，未创建查询账户状态。核心验证原本地记录拒绝官方服务预检，以及保护、模式切换、恢复、备注、备份导入失败时JSON/属性/数量不变。注入SCM未安装、查询失败、OS5、管道失联、错误宿主/版本/健康字段与畸形成功响应验证明确失败边界。lib与服务Clippy通过。官方同账户锁顺序不等于跨账户用户可写本地state的全局登记索引，后者仍须另行设计与验证。

## 已验证的核心行为

八项Windows核心实际IO测试通过：权限只读允许读取/枚举且拒写/新建；隐藏并锁定实际拒读；错误密码不改状态或文件；默认时长、到期、时钟回退、重启和停止前重锁；临时访问期间新增项目在重锁前登记；密码修改/移除和监控停用的验证；同一身份的ACL漂移修复；日志保存失败先关闭已登记内容且保持待重试；身份/父权限冲突不覆盖对象；显式目标SID与进程SID不同仍只限制目标SID。用户随后确认真实安装，LocalSystem服务12项实际NTFS/管道/SCM停止启动和异常自动恢复通过，GUI显示真实连接与可用入口，所有测试项目解除、当前账户零登记。最终工作区90项Rust、前端17项与全目标Clippy通过。第二账户、整机重启、服务卸载和原生GUI密码完整流程仍未验证，因此笔记暂留proposed记录剩余验收。

首次失败的夹具通过Windows继承正规化暴露了直接恢复子ACL的顺序要求，以及日志不可写时父项重锁影响未登记新子项的边界；前者以真实外部ACE变更测试，后者通过保留原ACE继承规则修复并加入回归用例，没有吞掉检查失败。

首次干净Windows CI运行40500699933暴露未安装服务时的宿主拒绝分类：SCM的ERROR_SERVICE_DOES_NOT_EXIST被通用IO分类为ReadFailed，伪服务测试要求PermissionDenied。生产身份核对现加显式PermissionDenied上下文并保留底层错误链；仍在发送请求前拒绝，未放宽伪服务测试或改成接受任意错误。本机已安装服务时同一测试走PID不匹配分支，因此必须保留干净runner证据。

## Alternatives considered

- 直接复用 Readonly 属性实现成本最低，但它对文件夹不提供写保护，因此保留为旧模式，新增权限策略。
- 内核 minifilter 可在 IO 路径判断访问，比用户态扫描及时，但需要驱动签名、安装与独立的系统故障恢复验收；用户态实现不作同等保证。
- 当前账户后台进程可复用现有账户和恢复状态，安装成本低；但重新启动后无法枚举被该账户拒绝读取的目录来补查新增项，用户已明确选择系统服务承担独立身份、IPC认证和所有权恢复的成本。
- 只在 UI 验证一个密码能最快呈现交互，但 CLI 和其他核心调用会绕开，截止后无法可靠重锁，因此核心统一校验，并让独立后台执行恢复计划。

## Acceptance criteria

- 权限只读真实 IO 证明可读取和枚举，写入、新建及范围内删除受限，切换及恢复原始权限正确。
- 密码错误不改变权限或记录；正确密码可临时访问，截止和立即重锁有效；重启及异常中断后计划可识别并重试，GUI/CLI 行为一致。
- 主窗口关闭后后台仍执行到期任务和新增项处理；能明确停止，停机、离线、外部身份冲突与失败有可见状态。
- 状态兼容、备份导入、逐项恢复和原有加密流程不回归；不依赖实际系统服务安装来伪造本地通过。

## Risks

原所有者可更改 DACL，密码模式不是恶意同账户或管理员安全边界。父目录 DELETE_CHILD 可允许根项目删除，不能宣称绝对防删除。后台修复必须核对身份与用户所选范围，不能覆盖换入的文件或扩大到范围外父目录。密码验证资料被删除或修改属于本地状态篡改边界；记录备份包含恢复敏感信息，需要在产品中说明。大目录扫描、通知溢出、文件占用和停止时机须实际验证。
