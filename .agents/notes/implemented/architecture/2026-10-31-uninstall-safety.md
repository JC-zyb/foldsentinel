# Agent Note: 卸载安全门与加密资产生命周期

Status: implemented

## Problem

卸载器只删除应用文件会留下仍需软件处理的加密包、受保护文件或中断恢复数据。可清空的界面历史没有完整资产状态，当前账户的服务列表也不能证明其他账户已经解除保护；失联、缺失记录和扫描失败若当作空状态，会在用户失去恢复入口后才暴露风险。

## Decision

NSIS 在删除任何产品文件前调用复制到插件临时目录的同一桌面 exe，使用 `--uninstall-prepare --parent-pid` 执行预检，删除后使用 `--uninstall-finish` 收尾。返回码 0 表示正常安全路径、10 表示已经交互式确认的强制路径，其他结果均停止。静默和被动模式拒绝强制返回码；公开的 `/UPDATE` 参数不构成绕过凭据。Tauri 的通用递归应用数据删除关闭，状态清理由 helper 按核实的固定范围执行。

生命周期门与 GUI、CLI 核心操作共用跨进程锁。预检必须取得独占锁，卸载会话保存父进程 PID 和创建时间；预检返回后，仍在运行的卸载进程阻止新的文件操作。卸载崩溃或取消且进程已退出后，重试可以清理过期会话。它用于正常软件入口的一致性，不隔离恶意同账户程序或管理员。

`vault-inventory.json` 独立于界面历史保存包头指纹、包位置、待提交/需恢复/已恢复状态与恢复位置。新加密输出提交前登记待提交，提交后标记需恢复；只有完整解密并提交输出后标记已恢复。取消或提交失败仅在输出明确未创建且父目录可读时回滚本次唯一待提交登记，否则保留未知状态并报错。成功验证和扫描发现的包登记位置；已登记项目无论位于哪个磁盘都核对。恢复输出保存根对象类型、卷序列号、文件 ID 和创建时间，卸载核对身份；允许同一对象内容正常编辑，拒绝同路径的文件/目录替换。缺少身份的旧恢复登记需要重新解密确认，不能用包丢失或同名空目录替代成功解密。身份记录不是内容哈希，不核对恢复目录中每个文件的后续完整性。

用户明确选择“本软件管理项目＋旧包扫描”，没有要求所有账户、所有磁盘逐文件扫描。旧包扫描通过 Windows Known Folder 查询当前账户桌面、文档、下载的实际路径，包含 OneDrive 等用户重定向位置，另检查 `%APPDATA%\FoldSentinel` 和 `%LOCALAPPDATA%\io.github.jc-zyb.foldsentinel`。内容头识别 v1/v2 包，不依赖扩展名。CLI `vault discover <paths...>` 允许先扫描自定旧包目录并登记发现，扫描不完整时返回错误；`vault inventory` 列出独立资产状态。扫描限额、拒绝访问、离线位置、重解析点和格式/索引错误均使正常卸载停止，不把跳过项当作已检查。范围不是全机加密文件证明。

正常路径检查本地保护登记为空、恢复任务及其目录为空、登记加密资产已恢复且输出身份匹配、旧包扫描完整。预检拒绝应用状态目录的未知条目、非空 `jobs` 和重解析点，收尾再次验证。可选服务还必须经管理员授权，核对固定 Program Files 程序、LocalSystem/OwnProcess 配置、正常停止退出码和全部 SID 的恢复记录。`uninstall_audit` 仅返回严格的数量/错误汇总，不向当前账户暴露其他账户路径；运行中的服务先通过在线全账户空审计才停止，停止后由固定服务程序进行第二次全账户只读空审计。第二次审计失败时尝试重启原运行服务并报告结果，覆盖审计与停止之间的新登记。成功移除 SCM 登记、白名单 exe 和空程序目录，ProgramData 恢复资料保留。

正常收尾清理核实的应用状态和固定 LocalAppData 产品目录内 `EBWebView` 树，删除本应用偏好与历史；删除前验证全部路径，遇未知根项、非普通文件类型、重解析点或锁定/IO 错误时拒绝或报收尾失败，不递归猜测用户文件。生命周期会话清除、释放锁后再删除固定锁和空目录。

NSIS 默认删除指令不保证目标已经消失。后置钩子在调用数据收尾前核对已知程序和系统入口的移除结果；文件被外部句柄占用等删除失败必须返回非零，保留恢复资料，不能仅依据 helper 的检查成功宣称完整卸载。

正常条件未满足时，强制卸载同窗显示阻止原因和中英免责声明，两次确认均默认“否”。确认后移除应用和独立服务，服务仍需管理员 UAC 授权；保留全部应用数据、ProgramData 资料、加密包、本地保护状态、资产索引和中断记录，受保护文件可能仍不可访问。强制服务路径要求实际 Stopped，但允许服务已停止且报告错误退出码，记录遗留保护风险；正常路径仍要求两项退出码均为 0。服务删除取消或失败时阻止卸载。静默卸载没有代确认通道。收尾失败明确报告，不能宣称完整卸载。

## Related decisions

当场检索活跃笔记后，[流式任务](2026-10-24-streaming-v2.md)和[日常流程](2026-10-24-daily-workflows.md)部分重叠，继续约束认证、提交和中断清理；本篇增加卸载对这些状态的依赖，不改变加密格式。[服务密码访问提案](../../proposed/feature/2026-10-27-managed-access.md)部分重叠，服务身份和恢复边界保留，真实第二账户/卸载验收没有被本次隔离测试吸收。[发布门禁](../process/2026-10-24-release-gates.md)部分重叠，本篇增加卸载钩子夹具，历史发布证据仍按原版本保存。首版格式兼容和 UI 排版笔记不受本决定取代。

## Alternatives considered

- 只检查 WebView 历史能够复用现有页面，但历史可清空且不覆盖 CLI、旧包或真实恢复结果，因此单独保存核心资产登记。
- 所有账户、所有磁盘完整扫描覆盖更广，但无法证明离线卷、无权限目录或其他账户内容为空；用户选定软件登记加旧包扫描范围，扫描内未知则停止，文档明示范围外旧包的登记方式。
- 只读当前账户服务列表最容易集成，但会漏掉其他 SID 的保护；采用不泄露路径的全账户汇总及管理员停止后的全量空审计。
- NSIS 默认“删除应用数据”能减少残留，但递归删除可能破坏原始 ACL、资产索引和中断恢复资料；禁用通用删除，正常路径只清核实安全的数据，强制路径保留恢复资料。
- 对 `/UPDATE` 或静默参数放行便于自动化，但参数可自行传入，也无法表达用户已经理解强制卸载后果；同一安全门适用于这些入口。

## Consequences

正常卸载会多一次扫描，服务存在时需要管理员操作；包曾在软件中出现但未恢复、索引损坏、扫描超限或未知数据都可能阻止正常卸载。收益是恢复前置条件进入核心与安装器契约，不依赖界面历史或用户记忆。强制卸载保留恢复机会，同时留下既有文件保护，用户需明确承担重新安装与后续恢复工作。已成功恢复的输出后续仍可能被其他程序修改；这项登记不是文件备份、内容快照或对抗管理员的证明。

版本同步为 0.8.0，保留 v1/v2 加密兼容和 v1/v2/v3 本地保护记录兼容，不把历史 v0.7.0 通过结果重写为新版本证据。源码更新和本地构建不等于已经发布 Release。

## Verification

核心回归覆盖生命周期共享/独占互斥与活会话、损坏会话、资产识别与恢复登记、恢复输出身份与同名替换、丢失/变化/迁移位置、待提交回滚、严格跨账户服务审计、正常卸载不得停止仍有受管项目的服务，以及强制路径实际停止与错误退出码边界。`validate-uninstall-hooks.ps1` 使用私有临时目录、私有注册表键和夹具 helper，直接等待卸载进程，检查正常、强制、阻止、未知返回码、静默/被动、更新参数、收尾失败、缺少 helper 及实际删除失败等共 18 项，严格断言实际退出码、删除前拦截、相同父进程和复制后的 helper 时序。真实禁止 DELETE 共享的文件句柄覆盖主程序、安装目录卸载器及产品快捷方式；卸载登记或自启动残留也在数据收尾前拒绝。有效其他目标快捷方式和未知用户文件保留；正常清理已知安装器偏好、强制保留、未知值保留，直接 `/UPDATE` 也清理实际卸载痕迹。NSIS 失败分支使用 `SetErrorLevel` 后 `Quit`，避免 `Abort` 使 UI 仍可能完成并覆盖错误码。`validate-service-uninstall.ps1` 仅加载被测函数并使用替身，验证白名单删除与拒绝未知内容、重解析点、错误退出码和非交互强制。

这些隔离检查不证明真实 UAC、SCM 删除、所有账户解除后的完整卸载或原生强制双确认已验收。最终当前工作区的命令结果、报告路径和未覆盖范围统一记录于[验证记录](../../../../docs/VALIDATION.md)，用户操作与数据保留规则见[安装与卸载](../../../../docs/INSTALL.md)。
