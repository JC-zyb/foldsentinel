# Agent Note: 双语任务与只读验证

Status: implemented

## Problem

v0.2 的单次任务与中文字符串接口不能支撑双语、批量队列和可重试历史。独立验证若另写解码器，容易与实际恢复的认证和归档规则产生差异。

## Decision

验证和恢复共用认证流与有界 tar 解析，验证把内容消费到 sink，不建立输出或任务临时目录。v1 保留 64 MiB 上限和固定参数，增加分段读取进度与取消检查；KDF 和单次 v1 AEAD 调用期间只能在调用结束后响应取消。

桌面错误跨 IPC 传递稳定类别，界面按当前语言呈现；底层诊断写到进程标准错误，不存储密码。语言表集中管理，首次使用系统语言，偏好持久保存，切换不重建正在运行的任务。

队列串行执行，密码仅在当前进程内存中保存至任务结束或移除，历史只保存路径、操作、时间、状态及错误类别。退出后未完成记录标为中断，重试必须重新输入密码。输出禁止覆盖，预检不能取代最终独占创建与提交；空间预检是保守估计，运行中 IO 错误仍明确暴露。

路径选择与拖放共用追加逻辑，按 Windows 大小写、分隔符及扩展前缀去重并保留首次输入顺序，便于分次添加文件和文件夹，避免后一次选择覆盖前次内容。列表可直接编辑；历史重填仍只填入对应任务，避免把其他来源误加入重试。

历史审计：[流式任务](2026-10-24-streaming-v2.md) 部分重叠，继续沿用其提交门与中断清理机制；[首版格式](2026-10-24-vault-and-desktop.md) 保留兼容约束；属性恢复笔记无关。本篇只扩展日常流程，不修改密码格式或 nonce 规则。

## Alternatives considered

- 前端按中文错误文本替换英文能少改 Rust，但依赖不稳定字符串且漏掉 IO 错误；改用稳定类别和本地化提示。
- 验证通过恢复到临时目录再删除能直接复用旧入口，但需要额外磁盘空间并留下临时明文；共享解析器，提供无输出目标。
- 并行任务可以提升多磁盘吞吐，但增加密码生命周期、取消和空间竞争复杂度；本阶段采用串行队列。

## Consequences

空间估计不能保证后续可用容量，目录和稀疏文件会影响实际占用。JavaScript 字符串无法保证原地清零，密码只限内存并及时释放引用；Rust 使用 Zeroizing。历史路径可能敏感，需要提供清空入口并说明保存在本机。

共享解析使只读验证与恢复采用相同认证和归档规则，无需临时明文。串行队列保持每次只有一个活动取消句柄；暂停保留等待任务的内存密码，退出后只恢复描述，重试必须重新输入。关闭窗口先暂停队列并取消当前任务，清理期间阻止默认销毁；提交门后仍等待完成，再次关闭才退出。

30 项 Rust 测试、5 项前端测试和 8 个真实子进程中断时机覆盖核心边界；桌面验证包含双语切换、批量加密/验证/恢复、错误密码重试、速度与取消、重启历史与中断状态。完整证据和未验证的发布、设备及安装边界见 [验证记录](../../../../docs/VALIDATION.md)。
