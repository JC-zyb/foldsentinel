# Agent Note: 流式格式与可恢复任务

Status: implemented

## Problem

v1 整包加载内存的 64 MiB 上限阻止日常大文件使用。长时间 IO 还需要真实进度、取消和强制终止后的残留处理。

## Decision

v2 使用 RustCrypto STREAM BE32 + AES-256-GCM，固定 1 MiB 明文分块，每个分块认证完整格式头，终块使用独立的 last 标记认证。解码必须看到终块且物理 EOF，才能提交输出；删除、重排、复制、跨包拼接和追加数据均不得成功。v1 解码与参数保留，新建加密包使用 v2。

`crypto.rs` 持有密码验证与固定 Argon2id 参数，`paths.rs` 持有输出与归档路径校验；当前格式及兼容解码均依赖这些公共能力，最新实现不依赖旧版模块获取通用能力。`reader.rs` 的 `PackageReader` 统一恢复、验证和预览的格式分派、包头与内容检查；`legacy.rs` 仅保留旧格式解码和测试生成支持。旧格式解码借用同一个稳定文件句柄并从起点读取，不按路径重开。读取器在提交与登记完成前持有句柄，避免完整认证后源包被改写或删除。提交门、资产登记与任务清理仍由外层入口管理；只读验证不创建恢复任务或临时明文。

文件与 tar 目录归档通过 Read/Write 流式适配器传输。目录预扫描总量并校验名称；扫描结果有条目与路径长度限制。每个文件读取前后检查大小、修改时间，发现源变化就停止，明确不提供快照语义。恢复先逐块认证到任务临时目录，仅在所有分块、归档和取消检查通过后提交。

恢复使用 tar raw 条目，先限定 GNU 长路径扩展大小再读取，拒绝 PAX、稀疏表及其他特殊扩展，避免默认 tar 预处理在路径校验前无界读取元数据。编码器只产生普通 GNU 文件/目录及有界长名称；旧 v1 解码仍有整包 64 MiB 限制。

任务临时目录位于目标父目录，同卷提交且禁止覆盖。恢复登记保存在本用户配置目录，持有跨进程文件锁；正常失败或取消显式清理，强制终止后可枚举、清理并重新输入密码重试。记录不保存密码或派生密钥。只允许清理标识匹配、无活动锁的自有任务临时目录，永不删除最终输出。取消的最终检查与提交共享互斥门；提交开始后 UI 明确显示不可取消。

清理先移除临时数据，最后移除所有者标记与活动锁，避免 payload 被占用时先丢掉所有权凭据。临时目录缺失而其父目录也不可访问时，按清理失败保留登记，不能把卷离线误认为数据已清除。带清理失败的 anyhow 类型化上下文优先呈现 Recovery，数字 IO 错误仍供脱敏诊断使用。

历史审计：[首版格式](2026-10-24-vault-and-desktop.md) 部分重叠，保留其 v1 兼容约束并互链。属性恢复笔记与本次流式设计无关。

v0.3 的[双语任务与只读验证](2026-10-24-daily-workflows.md) 共用本篇认证流、归档解析和提交门，增加任务队列及空间预检，保持格式与固定参数不变。

[发布门禁](../process/2026-10-24-release-gates.md)将版本、便携内容与校验和设为构建检查；实际安装及真实卷写满仍须独立证据，不扩展本篇密码或提交契约。

## Alternatives considered

- 整包加密实现简单、整包认证后才落盘明文，但内存随数据增长；v1 只保留解码兼容，不提高其上限。
- 自行组合 nonce 计数器能减少一个适配层，但容易遗漏终块与计数器边界；采用现有 STREAM 构造并验证其旧版本源码 API。
- 断点续传可节省重试时间，但需要新的源快照、密钥管理与 nonce 状态契约；本版只做中断识别、隔离残留清理和安全重试，不承诺续传或断电事务。
- 恢复与验证各自保留包头和内容消费代码，能直接看出各入口流程，但同一格式的检查容易分叉；采用内部共用读取器，输出创建与空间预检仅在恢复目标存在时执行，入口继续独立管理提交与登记。
- 移除旧解码器能进一步减少代码，但已有包不会因界面统一而自动转换；保留只读兼容分派，不引入自动重加密、格式升级或密钥参数变更。

## Verification

4 GiB 文件与 10 GiB 文件夹实际落盘、加密、恢复后 SHA-256 一致，核心验证进程累计峰值工作集约 25.9 MiB（阈值 256 MiB，不包含 WebView2）。旧版发布源码生成的文件/目录夹具兼容。测试覆盖块边界、终块、篡改、截断、重排、取消、写入失败、扩展名称限额、源变化及输出竞争。独立子进程在写入后被真实终止，识别清理及重试通过。原生 GUI 已验证中断列表、清理重填、真实输出、可见字节进度和取消后无输出/无任务残留。发布和 CI 证据统一记录在 [验证记录](../../../../docs/VALIDATION.md)。

公共读取器整理的回归直接调用生产 Rust 入口：越界内容／条目声明在恢复、验证、预览中均拒绝，目录 tar 结束后缺少认证终块同样拒绝；Windows 提交回调尝试改写和删除新旧格式源包均被拒绝，操作结束后句柄释放。上述检查与实际旧发布夹具、分块边界、错误密码和中断清理测试共同约束格式兼容，不以新生成器自测替代旧包证据。

2026-11-07 的最终工作区验证：`cargo test --workspace --locked` 共 151 项通过，1 项需要主动实网访问的更新检查保持忽略；`cargo clippy --workspace --all-targets --locked -- -D warnings`、`cargo fmt --all -- --check`、`git diff --check` 及笔记树／格式检查通过。本轮未重跑大容量性能测量、GUI 点验或安装器打包，不把上述历史大容量数据作为本次性能提升的证据。

## Consequences

固定内容缓冲使大文件可用，但目录仍需有界元数据清单，新版本不能被 v0.1 读取。自有格式需要独立审计。流式恢复在完成整包认证前写入已认证分块的临时明文；中断可能残留，不能宣称安全擦除。正常清理失败显式记录，拒绝无锁降级。中断恢复通过清理重试实现，不承担密钥持久化、源快照及 nonce 续传状态的复杂性。
