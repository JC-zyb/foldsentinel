# Agent Note: 首版加密包与桌面边界

Status: implemented

## Problem

隐藏和只读属性不保护内容机密性；首版需要用户能够创建、携带和恢复的加密副本，同时防止错误密码、输出覆盖及不可信归档写出目标目录。

## Decision

核心 Rust 库提供文件及目录加密包，CLI 和 Tauri 2 桌面共享同一实现。目录使用未压缩 tar，完整内容由 AES-256-GCM 认证后才恢复。Argon2id 参数固定在格式版本内，头部参与认证，格式见 [FORMAT](../../../../docs/FORMAT.md)。密码不进入命令行参数、配置或持久日志。

首版使用整包认证，限制为 64 MiB / 10,000 项。输出禁止覆盖，源数据始终保留。桌面耗时操作进入 blocking worker，前端仅暴露明确的业务命令和原生选择框，不开放 Shell 或通用文件系统 API。

v0.2 的新建加密改为 [流式 v2 与可恢复任务](2026-10-24-streaming-v2.md)。本文保留 v1 格式及固定参数兼容约束；整包路径只用于旧包解码，旧编码器仅保留为测试支持。

Windows 文件名不区分大小写，GUI 产物为 `FoldSentinel.exe`，CLI 必须使用独立名称 `foldsentinel-cli.exe`，避免同一 target 目录和便携包互相覆盖。

历史检索：仓库此前没有 `.agents/notes/`，没有重叠笔记；README 的未来架构保留驱动方向，但首版不实现服务或驱动。

## Alternatives considered

- 分块流式 AEAD 能支持大目录并降低内存占用，但需要额外设计顺序、终块和截断认证契约。首版采用有硬上限的整包格式，超限显式拒绝；大文件需求出现时设计新格式版本。
- 使用 age 格式可以复用成熟容器和外部工具，但密码方案及目录归档仍需组合；当前首版选择已实现的 Argon2id + AES-GCM，承担自有容器维护和审计成本，不宣称它比成熟格式更安全。
- 为桌面单独实现文件操作能减少桥接工作，但会出现 CLI 与界面行为分歧；共享核心保持同一失败和恢复策略。

## Consequences

可交付独立 Windows 桌面和 CLI，输出不依赖本地属性状态。首版不支持挂载、原位加密、透明拦截、管理员隔离或安全擦除；内存上限和元数据保真限制必须在 README 与界面说明。自有格式需要后续独立审计；不得无版本变更修改 v1 参数。

## Verification

核心测试覆盖二进制/空文件、Unicode 目录与空目录、错误密码、头部及密文篡改、截断、已有输出和路径校验。桌面交付前运行 TypeScript 检查、Rust 测试与 Clippy，并进行 Windows 原生窗口操作验证。
