# Agent Note: 隐藏属性在资源管理器中的可见性

Status: implemented

## Problem

Windows 资源管理器的“显示隐藏的项目”会绕过普通 Hidden 属性。FoldSentinel 原先只设置 Hidden，因此用户开启该选项后仍能看到受保护路径，界面“隐藏”容易被理解为不可见或安全隔离。

## Decision

隐藏和隐藏 + 只读模式同时设置 Hidden 与 System；只读模式仍只设置 Readonly。恢复记录的托管位扩展为 Hidden/System/Readonly，恢复时按记录还原三个位，保留其他属性及外部修改。界面和文档明确说明：资源管理器默认隐藏受保护的操作系统文件，所以仅开启“显示隐藏的项目”时通常仍隐藏；关闭该保护选项、使用其他文件管理器或具备权限的用户仍可看到内容。内容机密性继续由加密包提供。

## Alternatives considered

- 仅继续设置 Hidden 最符合属性名，但无法解决用户报告的资源管理器行为，因此放弃。
- 使用改名、ACL 或权限拒绝来制造不可见效果会改变用户数据、访问控制或恢复边界；这些机制也不能保证对管理员和其他工具不可见，因此不引入。
- 删除或移动文件会让内容暂时“消失”，但违反源数据保留和可恢复属性的产品契约，因此不采用。

## Consequences

默认资源管理器设置下的隐藏效果更符合用户预期；属性记录兼容旧状态文件，因为原始位仍按已有记录解释，重新应用策略时才会写入新的 System 位。系统属性仍不是安全边界，文档和 UI 必须持续避免把隐藏描述成加密或访问控制。Windows 属性测试需要在真实系统上检查 Hidden/System/Readonly 位；非 Windows 平台仍明确拒绝属性操作。

## Verification

- 单元测试覆盖三种策略的位组合、重复应用和原始位恢复。
- Windows 验证应确认仅开启“显示隐藏的项目”时资源管理器仍隐藏，关闭“隐藏受保护的操作系统文件”后项目可见。
- 本次本地开发继续保留干净 Windows、WebView2 缺失和原生 DPI 验收缺口。
