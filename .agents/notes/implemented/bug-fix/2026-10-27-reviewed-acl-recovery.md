# Agent Note: 权限冲突后的显式确认恢复

Status: implemented

## Problem

本地锁定后，资源管理器拒绝访问提示的“继续”可以为当前账户增加永久授权。目录仍有本应用添加的拒绝 ACE，内容访问仍受限，但 DACL 已不再等于登记的锁定状态。严格恢复因此拒绝覆盖，旧界面没有可核查的自助恢复出口。普通读取或枚举被拒绝本身不改变 ACL；不能把所有拒绝访问都归因于权限漂移。

## Decision

普通解除、核验、模式切换继续使用原有严格检查。仅最外层项目的“解除保护”在严格恢复遇到权限冲突后，自动执行只读核查；不再额外显示核查按钮。核查最外层登记项目的完整锁定子树，验证全部文件身份、NTFS、链接约束、原始描述符及范围外父继承，再返回不含路径或 ACL 的 SHA-256 状态摘要。仅完整带锁定恢复资料的子树可进入此流程。

界面明确说明确认会撤销保护之后新增或修改的权限，包括资源管理器后来授予的访问权限，文件内容不变；默认焦点留在取消按钮。确认提交重新读取记录、重新核对全部对象和摘要，状态变化使确认失效。首次写入前持有所有对象的禁共享删除句柄，按父到子恢复原始 DACL 与托管属性，全部完成后才删除恢复记录；写入或保存失败保留记录供重试。摘要不是密码或同账户安全边界，也不构成后台自动强制恢复。

新增的桌面命令只接受最外层不透明标识与摘要，路径及逐项权限留在核心。刷新清除界面的待确认摘要；文件替换、缺失、重解析点、多硬链接、父继承变化和服务范围冲突不能通过确认跳过。

历史审计：[独立 NTFS 锁定](../../implemented/feature/2026-10-27-ntfs-locking.md)部分重叠，保留默认冲突停止原则，本篇增加显式确认出口；[文件保护工作区](../../implemented/feature/2026-10-27-protection-workflow.md)部分重叠，沿用行内反馈、过期禁用和名称隐私；[恢复备份](../../implemented/feature/2026-10-27-protection-backups.md)部分重叠，仍保留原始恢复计划，不更改备份格式。没有完全吸收或过时提案。

## Alternatives considered

- 自动接受新增的当前账户完全控制 ACE 再写回原 DACL：操作最少，但会静默删除外部授权，因此不采用。
- 只删除本应用的拒绝 ACE并保留后来授权：可以解除访问限制，但不能声称已恢复原始继承；父项继承授权还会影响子项恢复及重试，需要另一套持久化合并计划，因此不混入本次修复。
- 保留原错误并要求手工修改 ACL：保持默认检查简单，但正常桌面用户无法完成恢复，因此把只读核查和明确确认接入现有解除流程，不另加一个入口，也不放宽普通核验。

## Consequences

完整原状恢复需要用户明确同意撤销后来的权限变更。核查和提交均线性读取所选子树并持有对象句柄；资源需求随登记数量增长，无法打开时在写入前停止。恢复记录格式保持 v3，合并入口不改 SYSTEM 服务或密码访问流程。

授权漂移测试构造的 SDDL 先通过 Windows 描述符转换规范化，再用于写入和结果核对。Windows 可将本机 RID 500/501 的完整 SID 输出为 LA/LG 别名，直接拼接完整 SID 会使测试在该账户下误报写入不一致。规范化仅供测试夹具使用，生产权限等价检查及写后核对保持不变。

核心回归覆盖授权漂移后的重启恢复、核查只读、确认后再次变化不写入、文件替换与范围外父变动拒绝；普通拒绝访问的隔离实测执行 400 次失败 IO 后仍可正常解除。桌面接口只返回摘要，不能披露内部路径。94项Rust、17项前端与48组浏览器布局检查通过。旧版独立核查入口的原生桌面检查确认核查和取消均零写入，明确确认后原DACL、身份、属性、内容哈希一致且登记归零；它不覆盖当前单入口自动弹出确认后的原生取消/确认交互，该项仍待验证。具体证据及未覆盖范围见[项目验证记录](../../../../docs/VALIDATION.md)。
