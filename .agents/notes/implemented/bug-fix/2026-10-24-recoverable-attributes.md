# Agent Note: 属性操作先保存恢复信息

Status: implemented

## Problem

逐项修改属性后才写状态，会在遍历失败或进程中断时丢失原始属性。多个进程还可能相互覆盖恢复记录。

## Decision

StateStore 在加载状态前持有独占文件锁，遍历及读取失败显式报错；拒绝重解析点，不越过目录联接。修改属性前先将完整恢复记录同步到随机临时文件，再替换状态文件。中途失败保留记录，用户可执行恢复。恢复只还原每条记录托管的位，保留其他程序对 Archive 等非托管位的更改。属性页读取当前位并标记记录是否与策略一致、路径是否缺失或无法读取；掩码兼容和状态读取见[属性状态](../feature/2026-10-27-attribute-status.md)。

恢复记录是“可恢复属性的原始信息”，不是当前访问控制状态；桌面和 CLI 均不能将记录存在等同于文件被隔离。不能保护包含自身恢复记录的目录，避免记录变成只读后阻塞保存。

历史检索：无既有属性恢复笔记；与 [加密与桌面边界](../architecture/2026-10-24-vault-and-desktop.md) 分别约束属性操作和内容保护。

## Alternatives considered

- 每修改一个文件就保存 JSON，能减少未执行记录，但大量小文件产生重复序列化和同步 IO。一次保存完整恢复信息允许重试与恢复，同时避免每项落盘。
- 失败时立即回滚属性，用户体验更接近事务；但回滚本身也可能遇到权限变更或设备移除。首版保留原始记录并显式报告失败，提供可重试恢复。

## Consequences

崩溃后可能留下尚未应用的记录，恢复它们是幂等操作；恢复记录可能因文件被替换而不再对应原对象，路径型属性工具不提供文件身份或安全边界。锁不可用时拒绝操作，不采用无锁降级。

## Verification

Windows 集成测试验证递归应用与恢复、重复保护保留原值、状态文件独占锁及损坏状态拒绝。退出码及桌面错误显示不能伪装成功。
