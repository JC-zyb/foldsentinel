# Agent Note: 安装器部署持续防护服务与准确状态

Status: implemented

## Problem

0.9.0 的安装器只部署 GUI，服务程序和管理脚本仅进入便携 ZIP。安装后界面把未安装、停止和身份校验失败统一显示为连接失败，用户无法在安装流程启用所需的密码访问与持续防护，也容易将部署缺口误认为服务启动故障。

## Decision

在 0.9.1 完整应用安装器中提供默认不勾选的服务选项。主程序仍按当前用户安装，选择服务才由同一 GUI 的固定安装参数请求 UAC；服务固定安装至受保护 Program Files 目录，以 LocalSystem 自动启动。安装器随包部署服务载荷，GUI 构建绑定载荷 SHA-256，提权入口不接受外部路径，原生安装持有拒绝写入和删除共享的源句柄并核对散列。

构建先生成服务，再生成含服务资源的 NSIS；仅打包时启用资源覆盖配置，干净 checkout 的单测和浏览器预览不依赖 release 产物。安装失败和 UAC 取消明确保留 GUI 可用状态，不谎报服务已完成。

已有官方服务先验证固定路径、账户、类型及协议，不覆盖运行中二进制；兼容服务复用，已停止时可在明确选择安装服务的流程中启动。目录残留、身份异常、资料损坏或无法确认时停止该部分，保留恢复资料。安装健康验证使用已认证的全账户只读汇总，避免为提权账户额外创建用户状态。

GUI 在原有服务 RPC 失败后另行只读查询 SCM，区分未安装、已停止、启动中、停止中、运行但连接失败、配置异常和无查询权限；只有通过原有管道认证和协议校验才显示已连接。用户随后明确要求安装时未选服务也能在使用时安装，因此 SCM 确认未安装时提供按需安装入口，复用同一 GUI 固定 UAC 与部署逻辑，不另建启动/停止管理中心。无参 IPC 单飞 guard 在实际阻塞 worker 结束后释放，取消或失败可重试；前端在全局忙状态结束后另行核对真实连接，不把部署退出码当作可登记状态。

用户明确要求卸载同时移除新增服务及注册表。继续使用既有全账户审计与独立服务删除入口，核实 SCM 登记消失后才视为删除完成；SCM 负责服务 HKLM 登记清理。安装目录内的服务载荷也须删除并核对。产品安装登记、自启动值按已知范围清理，未知项保留，ProgramData 恢复资料不作为解决启动问题的清理对象。

最终复核发现 SCM 注销后程序删除失败会使重试跳过服务目录。卸载专用查询同时检查 SCM 与固定程序目录，不改变其他业务的已安装判断；SCM 明确不存在时允许管理员继续清理白名单程序或空目录。未知内容和查询失败继续阻止完成，不以递归删除解决残留。

## Related decisions

当场审计：[卸载安全门](../architecture/2026-10-31-uninstall-safety.md)部分重叠，继续约束保护项目、全账户审计和删除结果；[发布门禁](../process/2026-10-24-release-gates.md)部分重叠，补充服务载荷的构建顺序与一致性；[服务密码访问](../../proposed/feature/2026-10-27-managed-access.md)部分重叠，保留身份和恢复边界及尚未完成的跨账户验收。[工作区交互](2026-10-31-ui-workspace.md)部分重叠，继续约束异步焦点和双语反馈。其他加密、属性和备份笔记无关，没有完全吸收的记录或过时提案。

## Alternatives considered

- 继续使用便携包中的管理员脚本最省改动，也保留排查手段，但普通安装器仍无法完成服务部署，并要求用户识别脚本和 PowerShell 版本；集成原生安装入口。
- 改为整个应用按机器安装可以统一管理员上下文，但会扩大权限与现有偏好、安装路径和升级行为的变化；仅服务部署单独提权。
- 完整服务安装/启动/停止管理中心增加第二套生命周期流程；按用户使用时安装的需求，只为确认未安装的状态增加安装入口，复用既有部署和卸载契约。

## Verification

完整构建使用 `scripts/package.ps1`，服务先于 GUI 生成并纳入资源配置。源程序与构建绑定散列核验由原生测试覆盖；打包校验检查 ZIP 服务散列及 NSIS File/Delete 指令，不把脚本检查描述为实际解包验收。

Rust 工作区 143 项通过、实网检查 1 项默认忽略；前端 18 项、服务状态及按需安装 UI 66 项、NSIS 安装钩子 8 项与卸载钩子 18 项通过。关键验证覆盖不同 SCM 状态、ACL 等价和拒绝其他写入者、源文件散列/共享/硬链接、拒绝覆盖、固定入口参数、失败结果与实际占用文件拒绝删除。新增 3 项真实文件回归覆盖文件占用解除后的清理重试、空目录和未知文件保留；桌面收尾在清理状态查询失败时保留恢复资料。UI 安装取消、失败、重复请求、未连接与焦点检查由元数据夹具验证，后端单飞 guard 另由真实线程回归覆盖；未执行实际服务安装。最新证据和产物范围见[验证记录](../../../../docs/VALIDATION.md)。

## Consequences

完整安装器可以明确安装服务，主程序不依赖额外 PowerShell 或补丁。代价是服务部署仍需要 UAC；复制后注册前失败会保留固定程序目录，后续安装拒绝自动接管，可先通过完整卸载器清理已知残留。已有兼容服务保留意味着程序不会自动升级服务二进制，协议不兼容时仍须先完成恢复与正常卸载。

服务启动会按既有逻辑读取 ProgramData 中的恢复计划并可能执行重锁，不能将存在旧资料的本机当作干净夹具。实际系统安装/卸载须在已确认范围与权限内验收；隔离 helper 或注册表夹具只验证分支和清理契约。未签名产物仍依赖用户核对来源，构建散列绑定不能替代代码签名。
