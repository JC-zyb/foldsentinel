# Agent Note: 桌面工作区布局与交互连续性

Status: implemented

## Problem

1080×820 默认界面的加入队列按钮位于约 y=934，选择、密码和确认均纵向堆叠，主操作需要滚动。视口断点会在内容仍宽时提前折行；保护列表的模式名称在中小尺寸被截断。服务区每次重绘都会收起说明，长列表下方打开的编辑器却在列表顶部且禁止焦点滚动。文件保护页的说明和备份展开后占据项目列表之前的大量空间，本地与服务操作缺少清楚的工作区边界；无登记时仍显示搜索、空范围和批量选择。

## Decision

表单沿用来源、密码、确认的 DOM 顺序，以主内容容器宽度决定双列或单列；保护记录按自身容器宽度降列。导航在窄窗口改为横排，模式文字在提交前保持可读。控件轮廓与辅助说明保持足够辨识度。

文件保护以“本地保护”和“密码与持续防护”两个页签划分任务，页签提供 tablist / tab / tabpanel 语义、单一 Tab 停靠点和方向键、Home / End 切换。添加文件、添加文件夹和次级路径输入属于本地工具栏；搜索和刷新属于项目列表标题区。项目列表置于添加操作之后，备份与恢复及适用范围说明置于列表之后，展开不会遮住项目入口。正文使用中性文字，蓝色用于行动和选中状态，不通过全局缩小字体增加密度。

只有成功读取、非过期且无全部登记的快照才能显示“尚无保护项目”引导并隐藏无用的搜索、范围统计、批量选择和分页。搜索无匹配仍保留查询；未提交的搜索输入也不因刷新被隐藏。未知、加载和读取失败分别反馈，失败保留原快照并禁用依赖有效记录的操作，不把空快照或旧快照解释成查询成功。

服务 UI 只在服务页签可见时轮询；离开时沿用组件的密码清理和编辑器收起，保留服务快照、本地草稿和本地搜索。返回主页面保留当前页签，恢复入口明确转到本地保护。界面切换不停止实际服务、不自动安装服务，也不绕过固定 UAC 和原有管道认证。

添加区在宽工作区按待添加项目与保护设置分列，窄窗口按 DOM 顺序堆叠；可选备注使用正常字重。无草稿不能应用，手动路径先明确加入草稿。全部成功后收起空表单，把摘要移到列表；刷新失败仍显式警告并保留过期状态，部分失败保留失败路径与备注。开始新批次清除上次结果；已移除失败项不得被重试，同路径恢复后重新登记也不得继承旧行反馈。后端失败可能已部分修改属性，实际执行批次后保守失效全部旧核验；不按名称猜测记录身份。未保存的无关行备注继续保留。完成后只在原操作焦点消失或仍停留时定位稳定标题，用户主动切页再返回的焦点不被抢回。

以下多文件“摘要 + 调整面板”记录保留原决策理由，其中方式入口与备注展开状态由[行内直接更改登记方式](2026-11-06-inline-registration-mode.md)部分替代；本篇其余工作区、快照与焦点约束继续适用。

多文件默认以名称/已保存备注、登记方式、核验状态及常用操作组成紧凑行；模式选择、重新应用及备注编辑集中在按需展开的全行编辑区。收起和 Escape 只改变显式展开状态，草稿和待应用方式分别保留，只有明确取消备注才丢弃备注。编辑器状态按记录 ID 保存在内存中，不按当前搜索或分页清理；恢复成功及导入替换记录时清理。待应用方式直接传组件，不通过重绘派发 change；摘要始终显示已登记方式，未应用标记单独呈现。过期快照仍可展开阅读但不能修改，错误与权限覆盖确认位于编辑器之外；异步焦点目标隐藏时回退可见的“调整”。

切换主页面聚焦新标题，导航与操作组有本地化名称。全局反馈位于页首，普通状态通过 live region 更新，不把正在编辑的焦点移到页尾；错误继续聚焦反馈。浏览器预览的自动导航不调用桌面读取接口，明确说明记录须在桌面程序读取。

服务重绘保留说明的 open 状态与 summary 焦点；异步刷新在禁用控件之前捕获焦点，用户主动转移焦点时不抢回。打开编辑器聚焦首个可用控件并允许滚动，无输入的确认表单也可见；取消后返回原行动作。队列重建按任务 ID 和动作保留焦点，原动作消失时聚焦稳定标题。暂停请求在队列附近显示，避免页首成功反馈离开视口后缺少确认。现有密码清理、显式提交、IPC 与权限语义继续沿用。

按用户指定的 design-taste-frontend 采用 preserve 审核：变化 3/10、动效 2/10、密度 6/10。该 Skill 的营销页大标题与装饰模式不适用于本工具的密集表单，采用其品牌保留、完整状态、双主题和对比度准则。颜色统一为语义变量，明暗主题自动跟随系统；深色主按钮填充与浅蓝链接分别定义，保证白色按钮文字对比，导航焦点使用适合深蓝背景的青色。

历史审计：[日常任务](../architecture/2026-10-24-daily-workflows.md)与[文件保护工作区](../feature/2026-10-27-protection-workflow.md)部分重叠，本篇补充布局和焦点；[服务提案](../../proposed/feature/2026-10-27-managed-access.md)继续记录服务安全边界与尚未完成的原生验收，本篇只解决界面状态连续性。其余命中的属性、备份、隐私列表与发布笔记无关，没有完全吸收的笔记或需要拒绝的旧提案。

## Alternatives considered

[服务部署与状态](2026-11-05-service-installation.md)补充未安装、停止和配置异常等准确状态，沿用本篇的异步焦点、旧快照和双语反馈约束。

设置页的[手动更新检查](../feature/2026-11-05-manual-update-check.md)沿用异步状态不抢焦点的约束；其网络、版本比较和链接边界由该笔记独立描述。

- 将队列固定到右侧便于观察任务，但默认窗口同时放来源、密码和队列会挤压路径及状态；采用表单双列，队列保留独立下方区域。
- 固定底部提交条始终可见，但会遮挡窄窗口内容与键盘焦点，且需重复主操作上下文；采用自然文档流，首屏显示默认表单提交动作，长清单保持局部滚动。
- 轮询时跳过已展开的服务说明实现简单，但会让持续阅读期间的服务状态停止更新；保留重绘并恢复展开与焦点。
- 为主题新增设置入口会增加操作与持久化契约；使用系统明暗偏好和原生 color-scheme，不增加依赖。
- 把说明默认折叠可以减少初始高度，但用户再次展开仍会把项目列表推走；将说明和备份放在列表之后，保留原生 details 的展开与键盘行为。
- 把本地和服务继续放在同一长页减少一次切换，但添加、密码、核验和安装会争夺首屏；使用页签隔离任务，同时保留各自草稿和真实状态。
- 保持完成后的添加表单可便于连续选择，但空草稿与旧成功结果会争夺列表上下文；全部成功收起、部分失败保留，新的选择重置结果。自动收起不以列表刷新成功为条件，刷新警告移到可见的列表区域。
- 所有记录常驻模式和备注控件可少一次展开，但多文件时行高掩盖文件间的比较；默认紧凑摘要加显式“调整”，保持核验和解除直接可用。未应用内容不因收起而丢失，代价是方式和备注编辑增加一次进入动作。

## Verification

`npm run build` 检查 TypeScript 和生产构建；`npm test` 检查 18 项工作流与双语契约。`scripts/validate-ui.mjs` 的 114 项检查覆盖 375–1440px、代表 DPR、中英界面、长路径、模式文字、默认提交首屏、导航焦点，以及服务说明重绘和长列表编辑器。独立 `validate-ui-states.mjs` 的 14 项检查覆盖真实队列与服务组件的动态焦点及暂停；`validate-ui-themes.mjs` 的 205 项检查覆盖明暗、中英、代表宽度和强制配色，等待动画稳定后，按实际祖先背景合成计算可见文字、占位文字、控件边界与焦点对比。

`validate-protection-layout-ui.mjs` 的 55 项检查和 48 张截图覆盖页签语义/键盘、项目列表顺序、真实空态/无匹配/读取失败、未提交查询、本地草稿与服务口令编辑器、选择及恢复确认，以及中英明暗的 375/720/1080px 布局。`validate-service-status-ui.mjs` 的 66 项回归继续验证各 SCM 状态、按需安装的取消/失败/重复请求和真实连接门槛。组件夹具不调用 IPC，不模拟文件操作成功。本轮没有执行真实服务或注册表修改；历史原生调试窗口的隔离包操作证据与本轮浏览器、构建结果分开记于 [UI 审核](../../../../docs/UI_REVIEW.md)。

添加流程另由 `validate-protection-add-ui.mjs` 的 56 项检查与 36 张截图验证。此脚本在本机浏览器模块响应中注入明确的内存 IPC，运行生产事件与状态转换，覆盖全部及部分失败、移除失败项后重试、同 ID 恢复再登记、失败后失效旧核验、刷新失败分离、取消晚回包和切页再返回焦点。模拟响应不证明真实文件保护成功，也不触及系统服务或注册表。

多文件修订由 `validate-protection-rows-ui.mjs` 的 70 项检查与 64 张截图覆盖 2/10/50 项、375/720/1080/1692px、中英文、明暗主题、显式展开/收起及未应用内容跨重绘保留、过期只读和权限恢复确认焦点。既有 UI 114 项、增加展开状态的主题 217 项、布局 55 项和添加流程 56 项回归通过。另按 856 CSS px / DPR 1.5 比对两个锁定无备注短名称，行高 65/64 CSS px，无横向溢出。此专项不调用 IPC，不模拟原生文件操作成功。

## Consequences

默认桌面窗口的主要输入与提交在首屏可见；不同内容区独立决定列数。文件保护的项目列表先于辅助资料，空态只保留有用操作；本地和服务间增加一次页签切换，并以停止隐藏界面轮询减少无关更新。代价是窄窗口和长选择仍需纵向滚动，CSS 依赖 WebView2 的容器查询支持。浏览器比例与当前原生窗口验证不能替代多种 Windows 原生 DPI、读屏软件或真实文件保护验收。
