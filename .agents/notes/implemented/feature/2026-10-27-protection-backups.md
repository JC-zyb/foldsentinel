# Agent Note: 本机恢复备份与添加备注事务

Status: implemented

## Problem

只在登记后编辑备注会使两个同名项目难以辨认。若先保护再另行保存初始备注，备注失败时用户会看到失败但文件已经改变。恢复原始属性与 ACL 又依赖完整登记状态，手工复制状态文件容易混入损坏或过期记录，直接导入覆盖正在使用的恢复计划会丢失原始信息。

## Decision

添加预检使用后台全部根名称及本批外层名称判断同名，只向界面返回下标、名称和同名标记。初始备注与原始属性、ACL 恢复计划共同在实际文件修改前原子保存；保存失败恢复内存且不修改文件。添加子项目若归并到已有祖先，非空初始备注明确拒绝，不能静默覆盖祖先备注。

备份导出为带格式及版本的 JSON 信封。完整状态和逐项卷序列号、文件 ID、创建时间通过随机密钥的 AES-GCM 认证加密，版本上下文作为附加认证数据。随机密钥由当前 Windows 账户的 DPAPI 保护，不使用机器范围标志，不写入密码或明文恢复内容。应用层 AES-GCM 认证避免仅依赖 DPAPI 对损坏输入的错误码。临时密钥和序列化明文使用 Zeroizing，DPAPI 输出密钥在释放系统内存前清零。

导出以独占创建提交，拒绝覆盖已有文件；需要对象元数据可读，且既有锁定身份仍匹配。导入只允许当前无登记项目，限制备份读取至 64 MiB，并验证格式、DPAPI 解封、AES-GCM、状态版本与索引、备注、逐项文件身份、托管属性、ACL 及父继承。不扫描新子项，不改变文件属性或权限；导入提交失败恢复旧内存状态。导入允许计划尚未应用或已恢复到原始状态的登记对象，以支持中断恢复，但外部状态冲突须先核查。

历史审计：[工作区与核验](2026-10-27-protection-workflow.md)部分重叠，沿用名称隐私、备注上限与单状态边界，本篇补充添加事务和备份；[NTFS 锁定](2026-10-27-ntfs-locking.md)部分重叠，复用身份、原始 / 计划 ACL 和父继承核对，不改变锁定策略。其余加密包、发布及属性决定没有被替代，没有命中的 rejected 提案。

## Alternatives considered

- 直接复制及导入原始 state.json 最容易人工检查，也方便迁移，但缺少账户绑定和完整性验证，导入过程还会把恢复记录内路径及权限作为不受信任输入；使用认证加密备份并在提交前核对实际对象。
- 由用户另设备份密码可跨账户恢复，但额外引入密码遗失、输入和密钥派生流程，本次目标是当前账户本机恢复；使用已有 Windows 账户密钥，明确不作为通用跨机迁移格式。
- 仅使用 DPAPI 最少代码且已有认证机制，但 Microsoft 明确提示损坏输入在部分情况下可能成功返回损坏内容；复用项目已有 AES-GCM 对实际载荷再做完整性验证。
- 保护成功后另存备注能复用现有接口，但两次持久化会产生“报错却已保护”的歧义；备注进入同一份保护计划。

## Verification

新增五项 Windows 核心测试和一项桌面测试覆盖实际隐藏 / 锁定、备注重载、计划保存失败未改权限、祖先合并拒绝、加密备份不披露名称或备注、导出不覆盖、非空状态拒绝导入、导入后重启并恢复内容、密文篡改、文件替换、非法掩码、外部 ACL 以及提交失败回滚。预检测试含超过一页的登记记录和本批同名，输出不含父路径。对应定向测试通过，不将当前账户测试推断为跨账户、原生 UI 或安装升级已验证。

## Consequences

恢复备份能保存完整计划并验证导入对象，初始备注失败不会改变文件。代价是备份依赖 Windows 账户密钥、当前对象身份及元数据可读，离线或被替换的对象会阻止安全导入；不提供直接覆盖、合并多个状态或跨电脑迁移。DPAPI 使用环境通常需要原账户及原电脑，漫游配置有平台例外，不能承诺账户失效后仍可解密。备份仍应随保护状态变化更新，旧备份不包含之后新增的项目。当前状态文件本身的存储方式没有因备份加密而改变。

技术依据：[CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)、[CryptUnprotectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptunprotectdata)。
