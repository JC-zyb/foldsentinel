# Agent Note: 设置页手动检查 GitHub 更新

Status: implemented

## Problem

设置页显示本地版本，但用户需要离开应用才能判断是否有可升级的发布。项目持续交付预览版，仅比较稳定版无法反映实际可下载的版本；联网失败也不能显示为“已是最新”。

## Decision

“关于”提供手动检查入口，通过桌面命令读取固定仓库的最近 100 条 GitHub 发布，包含预览版并排除草稿。后端复用锁定的 semver，按版本优先级选择最高版本；返回有更新、相同、本地较新或暂无发布四种结果。版本标签经校验后生成本项目固定发布页 URL，打开命令再次限制目标。检查和打开页面相互独立，发布说明按纯文本渲染。

网络由 Windows 原生 WinHTTP 处理，沿用系统代理与证书验证，关闭重定向、cookies 和自动认证。20 秒调用截止、18 秒内部预算、每阶段最多 5 秒、2 MiB 响应及 4 KiB 说明限制控制等待和内存占用。单次检查收尾前拒绝并发请求；异步 IPC 不阻塞文件任务或界面。错误保留为明确类别，用户可重试。

应用不会在启动时查询，也不会下载或安装；用户查看发布页后按现有升级流程操作。检查不发送本地路径、文件、密码或任务记录，结果只在当前窗口保留。双语状态使用 live region，不移动焦点。

历史审计：[发布门禁](../process/2026-10-24-release-gates.md)部分重叠，继续约束构建与产物；本篇只约束应用运行时查询。[工作区交互](../bug-fix/2026-10-31-ui-workspace.md)部分重叠，继续约束异步反馈与焦点。其余命中的加密、服务及卸载笔记无关，没有完全吸收的记录或需拒绝的旧提案。

## Alternatives considered

- GitHub 的 latest 接口响应更小且使用简单，但会排除本项目当前使用的预览版，无法满足实际升级判断；采用有界发布列表。
- 引入独立 HTTP 客户端可统一跨平台网络行为，但项目面向 Windows，现有 windows-sys 已能提供系统代理、证书验证与超时，无需扩大依赖栈；采用 WinHTTP。将来支持其他系统时应重新评估。
- 自动下载或安装可以减少升级步骤，但需要额外的签名验证、安装与恢复流程，当前功能只需判断版本并提供入口；保留手动下载。

## Verification

`cargo test -p foldsentinel-desktop updates::tests --locked` 覆盖版本排序、预览版、草稿、空列表与损坏响应、链接限制、响应及 Unicode 上限、HTTP 错误，以及超时返回后的并发与收尾。忽略的实网测试经主动执行，真实返回已发布 0.8.0，本地 0.9.0 状态为 ahead。`scripts/validate-updates-ui.mjs` 使用生产组件与合成发布元数据验证交互，不模拟文件操作，也不替代真实 GitHub 查询。完整验证结果与产物记录归入 [验证记录](../../../../docs/VALIDATION.md)。

## Consequences

用户能在设置中判断可升级版本，网络错误不会被误报为没有更新。代价是同步 WinHTTP 系统阶段在调用超时后可能仍需短暂收尾，其间返回忙碌；最近 100 条以外的发布不参与比较。如果发布量或支持平台改变，需要重访该上限和网络实现。浏览器组件验证不能证明原生默认浏览器或安装升级流程已验收。
