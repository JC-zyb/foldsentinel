# Agent Note: 最外层名称恢复列表

Status: implemented

## Problem

隐藏后仍须在重启时找到恢复入口，但逐项路径和属性明细会在工具页面暴露内部文件名。用户要求只以最外层文件或文件夹名称作为恢复记录，不能依赖用户再次找到隐藏路径。

## Decision

本地 `state.json` 继续保存完整路径、最外层索引及逐项原始属性，在文件属性变化前持久化。显示层不再接收逐项记录、父路径或状态文件位置；桌面列表接口仅返回最外层名称、内部标识和最外层分页数量。名称通过文本节点呈现，可访问性标签同样只使用名称，没有隐藏的路径 title 或表单回填。

恢复按钮把标识交回后台，由同一带锁的 StateStore 重新解析最外层路径再恢复。标识使用标准库对路径生成的散列，仅作本次列表定位，不持久化也不构成访问控制；算法升级后重新加载列表即可。失效标识和散列冲突明确拒绝，不能按列表位置或同名名称猜测目标。恢复两个同名目录时分别操作，列表名称相同也不合并。应用成功及页面切换清空新选择路径，恢复不重新写入输入框。

本决定取代[属性状态](2026-10-27-attribute-status.md)中图形页面展示逐项明细和完整路径的选择。核心状态读取、CLI 排查、v1/v2 掩码兼容及本地持久化仍成立；不改状态文件格式，不删除恢复所需的细项。当前图形列表不再进行逐项状态扫描，刷新只读取本地恢复索引。

历史审计：属性状态部分重叠并互链；[属性恢复](../bug-fix/2026-10-24-recoverable-attributes.md)及[隐藏可见性](../bug-fix/2026-10-27-hidden-attribute-visibility.md)部分重叠，保留先记录后修改与 Hidden/System 的边界。[双语任务](../architecture/2026-10-24-daily-workflows.md)、[认证预览](2026-10-24-authenticated-preview.md)、流式格式、首版加密和发布门禁仅共用页面或构建，不改变其决定；NTFS 锁定提案与此显示需求无关，保持 proposed。没有完全吸收或作废的提案，没有 rejected 记录命中。

## Alternatives considered

- 只在 CSS 中隐藏或折叠明细改动最少，还能随时展开排查，但完整路径仍进入 DOM、可访问性树和前端状态，不符合只显示最外层名称的隐私要求；从接口和组件一并移除。
- 前端只取 basename 并在闭包中保留原路径可以复用原恢复命令，但完整路径仍传给页面且容易再次被回填；由后台根据标识解析路径。
- 本地只保存最外层名称会减少落盘信息，却不能区分同名位置，也无法恢复各子项不同的原始属性；保留原有完整恢复文件，本次只收紧页面披露。

## Consequences

页面仅显示少量最外层记录，重启后仍能直接恢复；无新增依赖或第二份数据库。代价是同名项目的页面名称不可区分，且图形界面不再提供逐项状态排查，可通过 CLI 手动排查。本地恢复 JSON 仍包含完整路径且未加密，这不是元数据加密或访问隔离；加密本地记录和鉴权属于另外的需求，不能以本次显示收敛宣称已实现。

## Verification

桌面 Rust 测试使用两个同名目录及带私密标记的父路径、子文件，断言序列化白名单只有名称 / 标识、读取不写 JSON、重载后标识可定位、失效标识拒绝、两项分别恢复且内容保持。浏览器真实组件检查 DOM、aria、输入框与文本转义，不把合成布局数据等同于桌面操作成功。最终桌面与构建证据记在 `docs/VALIDATION.md`。
