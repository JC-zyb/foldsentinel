# Agent Note: 最外层名称恢复列表

Status: implemented

## Problem

隐藏后仍须在重启时找到恢复入口，但逐项路径和属性明细会在工具页面暴露内部文件名。用户要求只以最外层文件或文件夹名称作为恢复记录，不能依赖用户再次找到隐藏路径。

## Decision

本地 `state.json` 继续保存完整路径、最外层索引及逐项原始属性，在文件属性变化前持久化。显示层不接收逐项记录、父路径或状态文件位置；桌面列表接口返回最外层名称、内部标识、登记方式、用户自定备注、同名提示标记，以及过滤后和全部最外层数量。保护方式由 [NTFS 锁定](2026-10-27-ntfs-locking.md)扩展，用于按标识切换策略；备注、搜索和聚合核验由[文件保护工作区](2026-10-27-protection-workflow.md)扩展。名称及备注通过文本节点呈现，可访问性标签同样不含后台路径，没有隐藏的路径 title 或恢复表单回填。后台标识可用于 DOM 行定位与焦点恢复，但不含原路径，也不构成凭据。

恢复按钮把标识交回后台，由同一带锁的 StateStore 重新解析最外层路径再恢复。标识使用标准库对路径生成的散列，仅作本次列表定位，不持久化也不构成访问控制；算法升级后重新加载列表即可。失效标识和散列冲突明确拒绝，不能按列表位置或同名名称猜测目标。恢复两个同名目录时分别操作，列表名称相同也不合并；用户可自定备注区分。取消添加清空待保护路径，成功添加后移除成功项，失败项保留供处理；恢复不重新写入输入框。

本决定取代[属性状态](2026-10-27-attribute-status.md)中图形页面展示逐项明细和完整路径的选择。核心状态读取、CLI 排查、v1/v2 掩码兼容及本地持久化仍成立，不删除恢复所需的细项。列表刷新只读取本地恢复索引；后续[文件保护工作区](2026-10-27-protection-workflow.md)允许用户明确核验登记项目，但只返回聚合状态与时间。可缺省的备注元数据随 v3 状态保存，保持原属性与 ACL 记录格式不变。

历史审计：属性状态部分重叠并互链；[属性恢复](../bug-fix/2026-10-24-recoverable-attributes.md)及[隐藏可见性](../bug-fix/2026-10-27-hidden-attribute-visibility.md)部分重叠，保留先记录后修改与 Hidden/System 的边界。[双语任务](../architecture/2026-10-24-daily-workflows.md)、[认证预览](2026-10-24-authenticated-preview.md)、流式格式、首版加密和发布门禁仅共用页面或构建，不改变其决定。NTFS 锁定复用名称隐私边界并添加模式字段，仍不返回逐项扫描结果。没有完全吸收或作废的提案，没有 rejected 记录命中。

## Alternatives considered

- 只在 CSS 中隐藏或折叠明细改动最少，还能随时展开排查，但完整路径仍进入 DOM、可访问性树和前端状态，不符合只显示最外层名称的隐私要求；从接口和组件一并移除。
- 前端只取 basename 并在闭包中保留原路径可以复用原恢复命令，但完整路径仍传给页面且容易再次被回填；由后台根据标识解析路径。
- 本地只保存最外层名称会减少落盘信息，却不能区分同名位置，也无法恢复各子项不同的原始属性；保留原有完整恢复文件，本次只收紧页面披露。

## Consequences

页面仅显示最外层记录，重启后仍能直接恢复；无新增依赖或第二份数据库。同名项目需要用户填写有辨识意义的备注，图形界面仍不提供逐项状态排查，可通过 CLI 手动排查。本地恢复 JSON 仍包含完整路径且未加密，这不是元数据加密或访问隔离；用户自填备注也可能包含敏感内容，加密本地记录和鉴权属于另外的需求，不能以显示收敛宣称已实现。

## Verification

桌面 Rust 测试使用两个同名目录及带私密标记的父路径、子文件，检查列表字段白名单、读取不写 JSON、重载后标识可定位、失效标识拒绝、两项分别恢复且内容保持。浏览器真实组件检查 DOM、aria、输入框、备注、同名提示与文本转义，不把合成布局数据等同于桌面操作成功。最终桌面与构建证据记在 `docs/VALIDATION.md`。
