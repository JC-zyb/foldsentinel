# Agent Note: 属性状态读取与托管位兼容

Status: implemented

## Problem

管理记录只保存原始属性，不能证明保护已经生效。外部程序更改、旧版 Hidden 策略和应用中途失败都可能使实际属性不同于预期；把不一致统称为外部修改会误导排查。将 System 加入全局恢复掩码还会让旧记录覆盖本工具从未管理的位。

## Decision

图形页面披露范围由后续[最外层名称恢复列表](2026-10-27-private-recovery-list.md)部分取代：不再向图形页面返回逐项明细和完整路径。以下保留原先选择及其依据；核心实际属性读取、CLI、托管位兼容和本地持久化仍适用。

状态检查只读取记录对应路径，分别返回当前完整属性、原始属性、预期托管位和一致 / 不一致 / 缺失 / 无法读取状态。逐项隔离错误，不因单个路径失效隐藏其他记录。重解析点仍拒绝，不将记录当作文件身份或访问控制证明。界面每页检查 50 项并显示范围；切页或刷新明确重新读取，不后台修复差异，不声称扫描未登记的新子项。

恢复文件写入 version 2，每条记录保存 `managed_attributes`。v1 缺省掩码为 Hidden/Readonly；新隐藏模式取得 Hidden/System/Readonly 三个位的管理权，新只读模式仅管理 Hidden/Readonly。旧记录升级托管范围时，新增位以应用当时的值作为恢复原值，保留外部设置。状态读取接受 v1/v2 且不重写 JSON；下一次显式属性操作保存 v2，旧程序明确拒绝读取，避免其忽略掩码后留下 System。

状态比较只覆盖每条记录的托管位，Archive 等不影响一致性；完整数值和标签仍显示，未知位保留十六进制信息。无法读取显示“未取得”，不能当作零属性。旧版普通隐藏在 UI 中单独提示，是否重新应用由用户决定。

同一份本地 JSON 还保存 `roots` 最外层路径索引，与逐项原始属性在修改文件前同步写入。索引由已登记的路径祖先关系推导，父目录合并子项、重复应用去重、恢复后同步收缩；缺失路径仍保留，不通过磁盘扫描重新发现。旧 v1/v2 没有索引时只在内存中推导，下一次显式操作才落盘；非空索引与逐项记录不一致时显式报错。这样不引入第二份可能失步的数据库或 WebView 路径清单。

启动即加载本地管理记录，首页提示可查看并恢复；属性页在表单前列出最外层路径，每项可填入路径或恢复其全部已登记子项。根列表与逐项属性明细分别分页，不因大量子项挤掉其他根路径。列表只证明保存了恢复信息，路径失效或读取失败不自动删除；显式恢复才处理缺失项。

历史审计：[属性恢复](../bug-fix/2026-10-24-recoverable-attributes.md) 部分重叠，保留先保存再修改的恢复机制并扩展位归属；[隐藏可见性](../bug-fix/2026-10-27-hidden-attribute-visibility.md) 部分重叠，保留 Hidden + System 及其边界；[双语任务](../architecture/2026-10-24-daily-workflows.md) 仅共用 UI 和语言机制；预览、加密格式与发布门禁无运行时决定重叠，均保留。

## Alternatives considered

- 根据管理记录直接显示“已保护”省去文件系统读取，但不能发现应用失败或外部变化；选择显式刷新实际属性。
- 按当前三个位恢复全部旧记录可保持结构不变，但会覆盖旧版从未管理的 System；使用版本和逐项掩码表达归属。
- 每次进入页面检查全部路径更方便总览，但大量记录和离线位置会放大 IO；按页读取并显示总记录数，不声称全库均正常。
- 独立 SQLite 或 localStorage 路径清单可以单独检索，但当前 JSON 已保存全部恢复信息；另存会扩大依赖并引入双写失步，沿用单份带锁、临时文件替换的本地记录。

## Consequences

同一用户可辨认策略未生效、缺失和读取失败，恢复保留未托管位。新格式要求降级前先用新版恢复管理项目并备份状态；仅备份旧 JSON 不能撤销磁盘上已经变化的属性。此前未标记掩码的本地 System 隐藏补丁记录无法与普通 v1 区分，按旧记录保守处理，不猜测 System 是否由本工具设置。状态只是读取时刻的结果，路径可被替换，不能证明安全隔离。

## Verification

Windows 测试覆盖刷新不改 JSON、Archive 差异、System 差异、缺失与非法路径隔离、分页、v1 只读加载和升级、重复模式切换及恢复。前端区分未取得与零属性并验证中英文契约。真实 Windows 属性和桌面显示结果另记在 `docs/VALIDATION.md`，不将单元测试等同资源管理器验收。

持久化测试覆盖关闭 / 重新加载后根路径及数量保持、先子后父合并、同名前缀兄弟独立、部分子项恢复、按根独立恢复、旧记录与离线 UNC 索引推导、损坏索引拒绝及只读加载不重写。
