# Agent Note: 设置偏好与桌面后台行为

Status: implemented

## Problem

现有设置仅覆盖语言、外观、登录启动和手动更新。用户要求依次增加任务通知、历史管理、诊断与数据位置、默认操作偏好、窗口托盘及显示密度；这些选择涉及历史隐私、运行任务和退出边界，不能只增加无效开关。

## Decision

`ui/preferences.ts` 使用版本化 localStorage 键 `foldsentinel.preferences.v1` 和字段白名单，仅保存枚举、开关及用户明确选择的默认输出目录；缺少新增字段时采用默认值，已存在字段无效时明确报错。默认通知关闭，历史永久且保留路径以兼容当前行为，仍遵循队列最多 200 项的上限。可选保留 7、30、90 天；显示间距及字号默认标准。

`filterHistory` 只处理终态任务，期限基于结束时间，旧记录无结束时间时使用创建时间；同会话的等待及运行任务保留对象身份和必要执行路径。重启时旧等待及运行记录先转为 `interrupted`，再按终态历史应用期限与隐私策略；关闭路径保存时这些中断历史同样匿名，不能直接重试。关闭路径保存会将终态记录改为 `pathsHidden: true`、空源路径和空输出路径，并同步内存和持久化；这些记录不提供重试、再次检查或打开位置，重新开启路径保存不能恢复已删除路径。保留期限、匿名化和清空均有确认，旧队列清空入口也复用设置页确认，独立保护恢复记录不在这些操作范围内。

`TaskQueue` 每次保存前应用当前历史策略，保存成功后才替换内存；改变偏好时先保存偏好，再应用历史，历史保存失败则回滚偏好并显示错误。偏好损坏时使用 `preferencesBroken` 明确阻止添加、运行及队列持久化，启动阶段只读加载旧历史，不改写其磁盘原文；用户明确保存一项有效偏好后才能继续，避免读取异常重新开启历史路径保存。文件操作已经完成但最终历史保存失败时，保留真实终态并报告存储错误，不把文件结果伪装成待执行。密码不进入任务描述和任何设置存储。

默认保护方式为隐藏并锁定，只用于新添加；临时解锁默认为 5 分钟，可选 1、5、15、30、60 分钟，只用于新打开的解锁表单。输出目录默认为空，只填入新加密表单，不改已有草稿和队列；加密、恢复和验证输出草稿分别保留，切换到恢复不会继承自动填入的加密默认目录。通知可选关闭、仅失败、完成与失败，使用固定中英文文案，不带路径、备注、密码或错误原文；发送失败单独反馈，不改变文件任务结果。

`src-tauri/src/desktop.rs` 原生保存窗口偏好，关闭到托盘和启动后最小化默认关闭，托盘入口提供恢复窗口和退出；开启启动后最小化在下次启动时隐藏到托盘。关闭到托盘隐藏窗口并清空表单密码，队列按原流程继续。真正退出检查活动任务、前端忙碌状态及原生操作计数，忙碌时拒绝退出并恢复窗口；普通关闭仍遵守原有暂停和取消约束。前端关闭事件在托盘路径明确阻止默认窗口销毁，与原生 `prevent_close` 配合。窗口设置不修改 Windows 登录启动或 SYSTEM 服务配置，关闭 GUI 不停止独立服务。

数据目录查询与打开采用 `app_data / recovery / protection` 固定枚举，拒绝任意路径，不创建不存在的目录；诊断支持无当前错误时导出基础系统报告，继续使用封闭字段与独占创建，拒绝覆盖。浏览器预览禁用原生入口，不冒充系统通知、托盘、目录选择或诊断导出成功。

本决定部分扩展[日常工作流](../architecture/2026-10-24-daily-workflows.md)的历史和关闭规则；该笔记的串行、密码内存生命周期、文件独占提交及诊断隐私理由继续成立。[卸载安全](../architecture/2026-10-31-uninstall-safety.md)的恢复记录保持独立，不受清空历史影响。显示布局遵循[工作区](../bug-fix/2026-10-31-ui-workspace.md)。活跃笔记中无替代本次六类偏好的提案或拒绝决定，没有本次完全吸收而需归档的独立决定。

## Alternatives considered

- 全部偏好存到原生配置能集中管理，但要求前端历史和每次渲染均等待 IPC；通用显示/历史偏好沿用已有本地存储，影响启动可见性的窗口选项原生保存。
- 只在序列化时隐藏路径可少改内存队列，但界面仍能重试或暴露用户已要求隐藏的历史；使用同一历史策略同步内存与持久化，保留运行任务引用。
- 托盘关闭时取消当前任务能复用既有退出代码，但与“最小化到托盘继续运行”的选择冲突；隐藏与真正退出分别处理，活动任务阻止直接退出。

浏览器恢复元数据夹具只验证展示保持，不执行原生命令或模拟保护成功。真实打包程序的隔离启动／重启报告为 `work/v092-settings-final/native/report.json`，记录语言同步、原生窗口偏好、诊断及目录白名单、固定内容通知请求、重启隐藏到托盘并保留偏好 5 项检查；通知仅确认系统 API 请求成功。关闭隐藏后进程仍存活有真实检查，托盘显示／退出菜单尚未 UI 点验，通知实际送达及 Windows DPI 也不在这些证据内；最终验收范围见 [UI 审核](../../../../docs/UI_REVIEW.md)，不把部分系统请求或单元结果当作完整原生验收。

## Consequences

六组设置可独立保存，保持现有任务和保护记录的操作边界；历史与默认值由同一模型校验，减少存储和显示不一致。代价是窗口配置与 WebView 偏好分为两个存储，历史偏好与记录也需要失败回滚；出错时保留明确反馈，不能报告已保存。历史匿名化不可逆，并失去直接重试便利，必须操作前确认。

Windows 通知显示受系统策略控制，发送请求成功不代表用户已经看到通知。JavaScript 字符串不能保证原地清零，隐藏窗口清除的是表单密码，队列等待任务仍需保留内存密码直至结束、取消或退出。大字号和紧凑模式增加组合数量，当前浏览器覆盖只证明所列场景；新增控件或布局断点时需复查。数据目录可能尚未存在，此时明确失败，不自动建立或清理恢复目录。
